# MERIT、LongVT 与 VideoARM：QVHighlights 结果对比

分析日期：2026-10-15。此次只读取已冻结的预测、标签和运行记录，重新计算指标及配对统计；没有重新推理、训练、调整参数或恢复暂停的 VideoARM 任务。

公开更新日期：2026-10-16。[导出说明](PUBLICATION.md)区分原始输入哈希与公开文件哈希；原始机器路径已替换。新增的初始化审计和研究方案见下方链接。

## 主要结论

**MERIT 优于已有四组完整 LongVT 实验，但目前不能称为三种方案中最优。** 在 VideoARM 已完成的相同 419 条查询上，VideoARM 的两个主指标均高于 MERIT。前者是完整验证集结论，后者是经过完成/成功筛选的子集结论，必须分别报告。

## 完整验证集：MERIT 与 LongVT

五组均覆盖相同的 1,550 个查询、1,519 个视频片段、474 个源视频。采用同一版本的官方评价代码，失败保留零分预测向量后参加官方评测。下表为百分数；不是各论文原任务的复现成绩。

| 冻结方案 | Fair mAP / Hit@1 | Good mAP / Hit@1 | VeryGood mAP / Hit@1 | 失败回退 |
| --- | ---: | ---: | ---: | ---: |
| LongVT compact v1 Global | 30.96 / 28.97 | 24.47 / 26.97 | 13.90 / 20.65 | 16 |
| LongVT compact v1 Tool | 32.17 / 31.16 | 25.57 / 29.16 | 14.60 / 22.71 | 28 |
| LongVT v2b Global | 32.93 / 37.87 | 26.18 / 36.39 | 14.94 / 28.45 | 0 |
| LongVT v2b Tool | 33.38 / 35.81 | 26.52 / 33.81 | 15.12 / 27.23 | 0 |
| **MERIT 适配** | **46.69 / 41.68** | **37.85 / 39.42** | **21.67 / 31.23** | **9** |

v2b 是 GroundVTS 启发式输出协议，仍使用冻结 LongVT-RFT，没有 GroundVTS 的训练模块。

MERIT 相对 v2b Tool 的 VeryGood mAP 提升 **6.55 个百分点**，Hit@1 提升 **4.00 个百分点**。相对 Hit@1 更高的 v2b Global，提升分别为 6.73、2.77 个百分点。这是完整方案的观察差异；基础模型、抽帧、分辨率、输出表达和计算量均不同，不能单独归因于三键记忆或多轮检索。

对 474 个源视频做 10,000 次有放回配对 cluster bootstrap，seed=42，按查询加权，使用未四舍五入的逐查询指标：

| MERIT − 对照（VeryGood） | Δ mAP；95% CI | Δ Hit@1；95% CI |
| --- | ---: | ---: |
| compact v1 Global | +7.77；[7.15, 8.42] | +10.58；[8.33, 12.93] |
| compact v1 Tool | +7.07；[6.42, 7.74] | +8.52；[6.12, 10.97] |
| v2b Global | +6.73；[6.09, 7.39] | +2.77；[0.32, 5.32] |
| v2b Tool | +6.55；[5.87, 7.23] | +4.00；[1.46, 6.59] |

相对 v2b Tool，MERIT 的逐查询 VeryGood AP 为 1,145 胜、112 平、293 负。在五组均原生成功的 1,497 条查询上，MERIT 为 21.74 / 31.53，v2b Tool 为 15.19 / 27.39，优势也保留。因此，完整集差异不是仅由格式失败数量造成。

这些是事后探索性区间，未校正多重比较，也不覆盖模型、提示词和预算的系统差异。validation 在此前实验中已被查看，不能把它称作从未接触的测试集。

## VideoARM：同样本子集对比

正式 HD 运行保持暂停：成功 419、失败 34、暂停 4、未处理 1,093；计划总数 1,550。此次首次在归档预测上离线计算该 419 条成功子集的 HD 指标，并让其他方案严格使用同一批 qid。

| 方案 | 同一 419 条查询：VeryGood mAP | Hit@1 |
| --- | ---: | ---: |
| LongVT compact v1 Global | 13.67 | 18.38 |
| LongVT compact v1 Tool | 14.62 | 20.76 |
| LongVT v2b Global | 15.41 | 29.83 |
| LongVT v2b Tool | 15.11 | 27.92 |
| MERIT | 22.02 | 31.74 |
| **VideoARM M1** | **29.45** | **45.58** |

在这个子集上，VideoARM − MERIT 为 **+7.43 mAP、+13.84 Hit@1**。以 138 个源视频做相同的 bootstrap，区间分别为 [6.08, 8.78]、[8.35, 19.51] 个百分点。

其中 6 条 MERIT 使用了失败回退。仅保留两者均成功的 **413 条**，MERIT 为 **22.16 / 31.96**，VideoARM 为 **29.43 / 45.76**；差距仍在，不能用这 6 条失败解释。在全部六组均成功的 399 条上，方向也一致。

但 419 条是 VideoARM 完成且成功的选择子集，不是随机抽样，也没有包含其 34 条失败及未完成查询。置信区间不能消除这种选择偏差，**不能把 29.45 / 45.58 当作 VideoARM 的完整验证集成绩**。

VideoARM 与 MERIT 使用同一 Qwen3-VL-8B-Instruct revision，减少了一项混杂因素，但仍不是受控消融：VideoARM 初始化时对每个 2 秒 clip 直接采样图像并评分，图像最长边 672；MERIT 先构建 10 秒记忆，再将全视频描述、检索图像和邻域证据映射到 2 秒网格，最长边 448。两者提示词、局部工具、图像呈现次数和计算预算也不同。

一个值得验证的解释是：直接覆盖每个 2 秒区间的视觉评分更适合当前高光定位任务，而 10 秒描述对细粒度变化的保留不足。这是依据实现差异提出的假设，当前比较没有单独验证它，也不能证明 VideoARM 的控制器或记忆模块带来了全部增益。

## MERIT 的诊断与成本

### 初始化阶段的补充审计

从 VideoARM 的 419 条成功轨迹提取 Qwen 密集视觉评分初始化，得到 VeryGood mAP / Hit@1 **29.01 / 44.63**，最终为 **29.45 / 45.58**。其中双方均成功的 413 条上，初始化为 **29.00 / 44.79**，最终为 **29.43 / 45.76**。这是同一批已保存记录的离线评分，不是新启动的完整初始化基线实验。

初始化是本项目新增的 HD 评分适配，发生在控制器自主工具循环之前；其成绩不能归于 VideoARM 特有机制。完整方法对比也仍受到分辨率、提示词和取证预算差异影响。详见[审计结果](videoarm_initial_audit.json)、[逐查询结果](videoarm_initial_per_query.csv)、[审计脚本](videoarm_initial_audit.py)及[最新研究方案](../../../docs/research_directions_summary_2026-10-15.md)。

### MERIT 运行诊断

- **稳定性**：1,541/1,550 原生成功，9 条均在记忆阶段失败，失败率 0.58%。零分向量参加官方排序指标，并不意味着该查询的指标必然为零。
- **评分分辨率**：常数预测 35 条（2.26%），少于 LongVT v2b Tool 的 55 条；但最高分并列仍有 **1,444 条（93.16%）**，平均约 20.79 个区间共享最高分。MERIT 实际只用了 0/25/50/75/100 五个值，虽然输出范围允许 0–100。
- **Hit@1 敏感性**：官方固定选第一个最高分区间。若仅作诊断、均匀随机选择并列最高分，MERIT 的 VeryGood Hit@1 期望为 41.64，而官方值是 31.23。前者不是可替换的正式成绩；它说明并列处理会显著影响绝对值，需要改进区间间的区分能力，不能事后改规则提分。
- **检索轮数**：成功查询中 1/2/3 轮分别为 1,172/111/258 条。约 76.1% 一轮结束。这不能证明多轮无用，因为轮数由查询难度和模型判断共同决定。
- **成本**：已记录的累计 VLM 用量为 57,408 次请求尝试、约 **113.80M tokens**、643,567 次图像呈现（包括重复呈现和重试，不是独立帧数）。caption 与 key 生成占累计请求耗时约 **68.1%**；score 阶段占总 token 约 **52.6%**。
- **计时限制**：原报告的平均 query 时间 17.31 秒不是端到端耗时；成功查询不含记忆构建和索引，失败项记录到失败时的耗时。累计请求时间也不是 GPU 小时或完整墙钟时间。检索使用的 embedding 成本需另计。
- **比较限制**：MERIT 的 VLM 总 token 约为 LongVT v2b Tool 的 4.13 倍，但模型/tokenizer 不同，不能把这个比值当作严格 FLOPs 或速度比。当前结果支持质量优势，不支持等成本优势。

## VideoARM MR 与开发集结果

VideoARM MR 的 1,550 条计划查询已进入终态，成功 1,113、失败 437。成功子集官方 MR mAP 为 20.70，R1@0.5 为 42.32，R1@0.7 为 25.61；它们不是 HD 指标，不能与 MERIT 的 21.67 直接相减。原计划分母的失败指标记零结果是另一种自定义口径，不能混作完整官方预测提交。

历史 smoke/dev、低预算及 v1/v2 数据保留作工程记录。v1 有已登记的 stop 接口错误，开发集与验证集覆盖也不同；这些分数不用于正式方法排名。

## MERIT 与 VideoARM 的时间开销

在两者均成功的同一批 413 条查询（400 个视频片段）上，从 MERIT 记忆/查询记录和 VideoARM SQLite 账本提取耗时：

| 记录口径 | 平均秒/查询 | 中位数 | P95 |
| --- | ---: | ---: | ---: |
| MERIT 记忆构建 | 36.85 | 36.90 | 39.23 |
| MERIT 查询推理阶段 | 17.90 | 13.21 | 35.04 |
| MERIT 记忆构建＋查询推理 | 54.76 | 50.60 | 72.05 |
| VideoARM 单查询 active_seconds | 85.41 | 80.47 | 132.41 |

MERIT 的两阶段合计未包含抽帧、索引和外围开销；同一视频的多个查询在这里各计一次完整记忆构建时间，没有摊销。VideoARM 的 active_seconds 包含查询内工作以及并发服务等待。因此表中是现有记录口径的比较，不能将 85.41/54.76 直接解释为固有算法慢速比。413 条中 MERIT 的历史请求事件有 2 次缓存命中，VideoARM 没有共享缓存命中；记忆可以跨查询复用，但 17.90 秒仍不能作为完整在线端到端延迟。

实际运行吞吐则是另一种情况：

| 运行 | 并发查询 | 已记录墙钟时间 | 成功结果/小时 |
| --- | ---: | ---: | ---: |
| MERIT 完整主实验 | 1 | 22.61 小时；1,541 成功 / 1,550 终态 | 68.15 |
| VideoARM 部分 HD 验证 | 4 | 2.75 小时；419 成功、34 失败、4 暂停 | 152.41 |

VideoARM 当时的成功结果吞吐约为 MERIT 的 2.24 倍；这与四查询并发、服务配置和样本范围差异同时存在，不能推断同并发下仍有此倍数。MERIT 墙钟从 main 启动到 supervisor 完成，包含 smoke、恢复和评估，排除更早的模型/帧准备及已预生成记忆；VideoARM 计至用户暂停，包含失败和部分执行工作，排除服务启动。两者都采用两卡张量并行，但服务版本、显存预算及图像处理不同。

详细结果：[时间统计 JSON](timing_comparison.json)、[逐查询时间 CSV](timing_per_query.csv)、[读取脚本](timing_analyze.py)。这里只分析现有计时，没有重新启动服务进行速度测试。

## 对后续工作的含义

目前 MERIT 可以作为已经跑通、完整评估的研究基线。最值得研究的问题是：如何保留记忆检索的可复用性，同时减少从 10 秒语义描述到 2 秒高光定位的信息损失，以及减少最高分并列和重复评分成本。

如果继续做实验，首先需要同 Qwen3-VL、同抽帧/分辨率/预算下的直接密集评分对照，并补齐 VideoARM 的完整 HD 结果，才能判断记忆检索、控制器和局部细化各自的收益。这里只提出后续验证方向，没有启动额外实验。
