# 报告与代码同步发布约定

用户约定，生效日期：2026-10-22。

**以后每次按用户要求推送项目更新，都将本轮新增或更新的实验报告、结果分析、研究方案和文档索引一并推送。报告同步是推送任务的一部分。**

## 发布位置与检查范围

- 远程：`git@github.com:irryxeek/MERIT-based-method.git`，默认分支 `main`。
- 研究工作区与发布仓库是两个目录；先检查发布仓库的远程、分支和未提交修改，再同步文件。
- 检查研究工作区 `docs/` 下的新增和变更 Markdown，及本轮涉及的相邻零样本项目报告。不能只检查代码目录或沿用上次的短文件清单。
- 更新项目 README、文档索引和报告之间的引用。新报告应提供远程可点击入口。
- 尚未启动的方案、开发集、成功子集和完整实验分别注明；历史计划中的运行状态保留其日期，不替换成未经核实的当前状态。

## 内容与路径处理

报告的指标、样本范围、成本、失败和结论必须与研究工作区一致。发布副本可增加说明、调整链接及路径别名，不能为了发布改变实验事实。

本轮涉及的详细报告应随汇总报告一起同步。原始视频、模型、完整缓存、机器状态指针和未选择公开的原始运行产物不因报告同步而自动上传；相关引用可注明为本地资料。不要用“本地资料”标记代替上传本轮应发布的报告。

公开报告中的机器路径使用以下别名；它们表示原实验来源，不代表发布仓库附带这些目录：

| 别名 | 含义 |
|---|---|
| `$MERIT_ROOT` | MERIT 研究工作区 |
| `$ZEROSHOT_ROOT` | 零样本方法研究工作区 |
| `$LONGVT_ROOT` / `$VIDEOARM_ROOT` | 历史对照工作区 |
| `$MERIT_ARTIFACT_ROOT` | MERIT 原始运行产物根目录 |
| `$ZEROSHOT_ARTIFACT_ROOT` | REZE / 零样本原始运行产物根目录 |
| `$SHARED_DATA_ROOT` | 共用数据、模型与运行环境 |
| `$WORKSPACE_PARENT` / `$DATA_PARENT` | 其他工作区或数据目录的上级位置 |

历史命令中的服务名和 GPU 编号仅为运行记录，不能直接视为当前任务的启动设置。`AGENTS.md` 按原用户要求保持原样；本约定通过 README 和文档索引提供入口。

## 每次推送的完成条件

1. 检查并同步全部相关报告；已有发布状态说明、冻结计划和来源清单需要保留，新增说明另行记录。
2. 核对发布前后指标表与结论，检查仓库内链接，记录来源和公开副本的 SHA-256；旧冻结清单不追溯改写。
3. 明确选择暂存文件，运行 `git diff --cached --check` 并审阅变更；不批量提交大型运行目录或无关文件。
4. 提交并推送后，核对远程分支提交与本地一致，向用户提供提交号和关键报告链接。

本约定用于用户要求的推送操作，不自动启动实验或定时推送。当前同步覆盖情况见发布仓库中的 `docs/report_publication_manifest.json`。

## 代码补齐后的同步检查

新增或修改的实验源码、配置示例、测试和复现入口与报告一并核对。发布仓库的 `docs/code_publication_manifest.json` 记录源码来源与公开副本哈希；独立编写的发布工具也纳入校验。保留 `comparisons/` 和历史发布凭证。

在发布仓库执行 `python scripts/verify_publication.py`。提供 `--merit-source` 和 `--zeroshot-source` 的本机路径后，还检查研究目录中新增或变化的源码及报告，避免仅凭 `git status` 判断全部同步。两份清单须在编辑完成后更新，再校验、审阅暂存区并推送。

后续新增实验优先在 Git 管理的仓库中开发，原研究目录继续保留历史来源和缓存绑定。
