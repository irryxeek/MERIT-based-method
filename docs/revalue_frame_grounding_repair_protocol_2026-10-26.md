# ReVALUE 事实来源绑定与单帧观察修复协议

日期：2026-10-26。依据[上一轮结果](revalue_r2_observation_probe_results_2026-10-26.md)，先修复时间归属接口，再检验局部观察内容。此协议在新推理前冻结；原 R2、28 次中性观察及其失败证据保留。

## 1. 修复内容

- 每条事实的帧 ID、PTS、目标区间及片内／片外／跨界关系均由后端计算，模型不生成时间和来源。
- 采用源帧的半开显示区间。完整落在目标内才标为 `inside`；边界帧标为 `boundary`；多帧跨区标为 `mixed`，不以宽松容差算作片内。
- 片外、跨界事实保留观察锚点，但 `candidate=null`，不得作为目标候选的直接引用。时间在片内也不等于完整事件归属或文本正确，相关状态继续标为未核验。
- 时间元数据随活动记忆保留并计入 1,024-token 上限；引用校验重新计算范围，拒绝篡改或矛盾字段。原记忆排序和整条淘汰规则保持不变。
- 接口通过 `temporal_v1` 显式启用，旧冻结运行继续使用旧源码。新内容观察器先独立验证，不直接改写正式评分路径。

## 2. CPU 对照：只改变来源接口

固定原七条实际回看样本、28 份原始响应和文本，重放 14 份旧活动记忆，要求逐项一致；随后只补全来源字段、移除片外候选归属，检查容量与直接引用。

报告所有事实的时间分类、保留与淘汰，不能把片外数量当成事实错误数，也不能把来源校验通过当成语义正确。

## 3. GPU 对照：逐帧独立提取

固定 `5172、881、9841、7971、2973、3478、1129`，均匀/定向各两次观察，使用全部 **672 个原帧次**，不根据指标或新结果筛选。模型、权重、缩放后像素及解码参数延续上一轮。

每次只输入一张源图像，并复制成两帧适配现有视频编码器；因此有 1,344 张模型展示帧，672 个源帧次，没有新增源画面内容。不同观察可能包含同一源帧，不将 672 宣称为去重后的帧数。

提示不提供 query、目标候选、旧记忆或相邻画面。模型输出一句可见描述及可选不确定项；帧引用和时间由代码赋值。单帧不能确认动作过程、事件结果或前后关系，此轮只检查静态可见内容。

这是一项“局部输入＋后端绑定”的组合修复，不声称同时保持原提示、schema 和输出长度，也不能用它单独估计每项修改的因果贡献。上一步 CPU 对照另行隔离接口影响。

## 4. 预算与恢复

- 672 次正式调用，语义重试 0，额外请求 0；每次输出最多 160 token，输入加预留输出最多 2,048 token。
- 每观察组最多 688,128 token，总预留上限 1,376,256；实际输入、输出与上一轮 100,220 token 对比，历史费用保留。
- 最多两个 GPU worker，每槽累计最多 1 GPU 小时，总计最多 2 GPU 小时；用服务全生命周期报告实际占卡成本。仅使用启动时两次确认空闲的 GPU，核验 UUID。
- 原子共享请求账本、分槽锁和逐帧检查点；有效/无效响应均不重新生成。进程意外中断须先核算时间，不重置预算。队列最长 72 小时。
- 单槽服务运行上限 3,500 秒，清理最多 40 秒；模型调用前保留清理时间。异常和预算耗尽保留部分结果，不扩大额度。

## 5. 验证与退出

技术验收包括旧记忆重放一致、原/缩放像素一致、来源映射确定、片外不可直接引用、预算与缓存校验。所有 672 帧次保留分母，失败和空观察单列。

语义审阅预先固定每个观察的第 0、4、8、12、16、20、23 帧，另加上一轮已记录的错误帧：1129 的 s1122/s1214/s1410/s1461、881 的 s2513、5172 的 s1291、9841 的 s2197；实际存在的帧全部纳入。比较其原始/中性描述与新描述，覆盖七个案例。助手核对与独立人工审阅分别记录，后者未进行则保持未评。

本轮不运行新的高光评分、100 条 R2、R3/R4 或全量验证。只有观察内容核查支持修复后，才另冻结合适规模的比较实验；不能把单帧静态描述通过等同于完成高光 Agent 或证明精度提高。
