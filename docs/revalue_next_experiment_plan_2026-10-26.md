本计划接续[来源绑定修复与单帧验证结果](revalue_frame_grounding_repair_results_2026-10-26.md)，细化[现阶段方案](revalue_current_experiment_plan_2026-10-26.md)的最小对照阶段；[总体设计 v3](revalue_execution_plan_v3_2026-10-23.md)、历史冻结协议、预测及停止决定继续保留。

## 1. 推进结论与证据边界

**先用 CPU 验证来源信息能否无损压缩，再用固定七条回看样本检验“同事实换表示”和“补回旧证据”。观察内容可靠性是后续扩大评分实验的前置条件。**

| 已有证据 | 对下一步的约束 |
|---|---|
| R2 开发 100 条：E_memory mAP 44.49，均匀/定向观察均为 44.41；技术回退已降为 0 | 工程成功尚未转化为精度收益，不直接扩大样本 |
| 14 份记忆加入完整时间来源后，旧事实淘汰合计由 81 增至 167 | 应单独测试表示开销；计数按视图累计，不是独立事实数 |
| 1129 的旧均匀观察没有淘汰旧事实也出现退化；881 的旧赢家依据仍在 | 淘汰不是唯一原因，不能预设补回事实必然有效 |
| 672 次单帧观察纠正部分跨场景错误，但仍有细节误判；token 成本为前轮 2.57 倍 | 单帧核查保留为诊断能力，暂不全面替换观察器 |
| 400 次排序导出重放一致 | 本轮固定四态比较和排序规则，不用强制赢家制造改善 |

当前优先修复 A（记忆）与 B（观察）的证据接口；C（比较）的目的、四态判断保持原设定。D（事件交付）及完整闭环仍属于后续 R3，不把局部重排称为完整 Agent。

## 2. 样本、输入与检验假设

沿用已冻结诊断母集：原 R1 20 条与全部七条实际回看样本并集，共 **23 条**。实际干预样本固定为：

```text
5172, 881, 9841, 7971, 2973, 3478, 1129
```

其余 16 条为无回看兼容性对照：9429、5370、10272、8963、1058、8025、9196、5073、764、7795、5967、6468、1910、7050、10249、3202。原 R1 与回看集合交集四条，新增三条单列；不按 GT 或指标重新选样。

两观察臂各两动作，形成 **7 query × 2 臂 = 14 份活动记忆**。使用原 R2 的 28 份观察响应、79 条可见事实及原有 unknown 项；它们含已知语义错误，本轮不改写描述，不换入新生成的单帧事实。

- **H1，表示开销：**事实、顺序和来源含义相同时，紧凑编码可以减少活动记忆 token，并维持来源校验能力。
- **H2，证据保留：**在同一紧凑表示中，只补回被容量挤出的旧活动记忆条目，能恢复有用区分证据，且不增加无依据判断。
- **反证可能：**若增加旧证据仍不能改善判断，或变化主要来自原观察错误，则停止扩展记忆策略，转向观察内容或比较语义的单独诊断。

七条是反复查看的、由旧控制器触发的开发案例，对应七个源视频单位；两臂、候选对和帧不是独立样本。本轮不能估计普遍精度收益、模型自主规划能力或全量泛化效果。

## 3. P0：CPU 来源表示与容量检查

先实现一种确定性、可逆的紧凑表示，不调用 LLM 压缩。允许同一记忆内部共享候选区间、帧时间和状态表，减少重复字段；保留事实文本、ID、源时间精度、直接候选归属、片内/片外/跨界、未核验状态。

**全部模型可见内容，包括共享表、索引和解释图例，都计入 1,024 tokenizer token。** 后端可保留完整审计记录，但不能把已淘汰文本通过外部指针、隐藏提示或原始事实库送回比较器。模型看见的编码必须足以解读来源；不得靠省略时间或默认“已验证”节省空间。

分别检查两种情况：先固定同一事实集合测编码节省，再在同容量下测能追加多少旧条目。不得把编码和保留集合同时变化称为单因素表示实验。

CPU 交付与门槛：

1. 14 份基准来源记忆可以精确重建；紧凑表示解码后，文本、ID、来源和允许引用集合完全一致。
2. 14/14 份均 ≤1,024 token；片外、跨界和 unknown 均不能绕过直接引用校验。篡改时间、错配帧和伪造候选应被拒绝。
3. 同事实紧凑视图逐份不比完整表示更长；报告 token、元数据占比、候选覆盖及旧事实保留的逐份变化。
4. 若少于 7/14 份能完整追加至少一个含非 unknown 事实的原旧条目，暂不启动下述 840 次实验；保留容量负结果，不通过改写文本或提高容量救场。该门槛只是本轮开销筛选规则，不是精度门槛。
5. 16 条无回看路径的输入、缓存绑定和原预测保持一致。兼容性失败先修复，不将它们额外重跑后算作观察收益。

实现重点为 `memory.py`、`evidence_grounding.py`、`r2_planner.py` 及独立诊断运行器；现有函数尚不具备本文的紧凑编码和追加策略，不能直接以旧命令启动本计划。

## 4. P1：三条件小规模比较，最多 840 次

CPU 门槛通过后，冻结全部视图和请求，再运行以下矩阵。这里的 A/B/C 是实验条件，不是框架模块编号。

| 条件 | 来源表示与事实集合 | 作用 | 正式比较数 |
|---|---|---|---:|
| A：完整来源 | 当前 `temporal_v1` + 原新事实优先策略形成的集合 S0 | 修复后来源接口的真实比较基准；此前仅有 CPU 容量对照 | 280 |
| B：紧凑、同事实 | 将 A 的 S0 无损编码，文本、条目与事实顺序一致；省出的空间暂时留空 | A→B 检验表示方式对判断的影响 | 280 |
| C：紧凑、追加旧条目 | 保持 B 的全部内容，只向末尾追加原活动记忆中因容量被淘汰的旧条目 | B→C 检验追加旧证据的作用 | 280 |

每条件为 `7 query × 2 观察臂 × 20 有向比较 = 280` 次，三个条件合计 **840 次**。均匀和定向臂分别报告，不把两臂当作 14 条独立 query。16 条兼容性对照只使用核验一致的历史输出，不增加推理。

### C 条件的固定追加规则

只从观察前 E_memory 的活动 `items` 取条目，不访问已不在活动记忆里的原始事实。沿用当前旧条目的排序键：是否不属于观察锚点、最小锚点编号、排序后的 fact ID，原条目位置作稳定兜底。按此顺序处理未保留条目，完整追加至 B 尾部；若超 1,024 token 则跳过，继续检查下一条。

不重复已有 ID，不重写事实，不改变 S0 的文本和顺序，不引入新的语义去重或价值打分。已存在的来源索引保持稳定；共享表增量也计入容量。该条件只支持“追加保留旧证据”的结论，不能概括为“关键记忆选择算法已验证”。

### 共同固定项

固定 Qwen3-VL-8B-Instruct 原 revision、BF16、temperature 0、TaskSpec、Top-5 候选、旧视觉输入、原观察问题和帧、比较提示正文、四态 schema、引用规则及原分数置换。紧凑格式的解释放入计费的记忆视图，不顺带修改价值比较指令。

比较器仍读取每侧至多四张原候选帧，**不是纯文本 memory-only**。新增观察请求为 0、新增源画面为 0，但正式比较最多展示 `840 × 8 = 6,720` 帧次；重复展示照常计入计算成本。已获取的观察有历史成本，不能因本轮复用记为方法端到端成本为零。

旧 E0、C_direct4、E_memory 和旧观察结果仅作背景参照；它们不能替代新条件 A，也不构成本轮只改变表示的因果对照。

## 5. 预算、恢复与执行前冻结

| 项目 | 本轮上限 |
|---|---:|
| 正式逻辑请求 | 840；不另加模型 smoke、压缩或规划请求 |
| 瞬时故障追加 | 全局最多 42，每个请求最多追加一次 |
| 总模型尝试 | 882，包含失败、中断和追加 |
| 每次输出 | 384 token，保持现比较协议 |
| 每次输入＋预留输出 | ≤4,096 token，按真实多模态展开计数 |
| 共享绝对 token 上限 | **3,612,672 = 882 × 4,096** |
| GPU 服务生命周期 | 总计 ≤2 GPU 小时，含加载、推理及清理 |

历史对应 280 次比较的输入范围为 2,252–2,439 token，含 384 输出预留的最大值为 2,823；这支持预算可行性，但不是新请求已通过预检。若请求超过新上限，启动前停止并修订下一版本，不静默截断文本、来源或帧。

目前后端只有模型上下文检查和原条件预算，**尚未硬性实现本表的单请求 4,096 与全局 3,612,672 限额**。新运行器须在原子共享账本预留前增加硬检查及回归测试。无独立模型请求的 smoke 可以使用 CPU 夹具；若确需真实工程试跑，只能取已冻结的正式任务，计入 840。

采用最多两张确认空闲的 GPU，可并行独立请求；每槽生命周期累计 ≤1 小时，并为退出清理预留时间。占卡预算不等于完成耗时承诺。按用户授权选择任意空闲卡，无 GPU 6 保留队列，不中断其他任务。

断点、原始响应及失败均保留；重启不清零预算。仅明确瞬时运行故障可追加，语义错误、无赢家、无效引用、输出不满意或长度问题不能重生成。缓存校验模型、提示、schema、像素和完整输入；只有 qid 相同不构成复用依据。全局预算先耗尽则保存部分结果并停止，不借用旧轮剩余额度。

执行前保存新协议、源码/提示快照、23 条角色清单、14 份 A/B/C 视图及哈希、请求列表、父记录校验、成本限制和停止规则。运行产物使用新的 `$ZEROSHOT_ARTIFACT_ROOT/revalue_memory_compaction_v1_<启动日期>/`，不覆盖父目录。

## 6. 评价、继续与停止规则

先冻结预测和账本，再读取标签。推理输入不含 GT、正确高光数量或本轮指标。

**主诊断指标：**同事实 token 节省、完整旧条目和事实保留数（非 unknown 单列）、候选覆盖、直接引用合法性、双向结论转换、technical fallback、有效证据与理由是否一致。对 A→B、B→C 所有变化的双向候选对检查两侧来源，审阅全部新增确定胜负；恢复旧赢家本身不等于正确。保留无变化样本作为参照。助手审阅和独立人工审阅分别记录，后者未做则保持未评。

**次指标：**逐 query 的 VeryGood mAP / Hit@1、修正与误改、tie/insufficient/胜负分布、token 和 GPU 时间。报告七条干预集、16 条兼容性集和23条描述性汇总，不能把未干预样本复制进多个臂来夸大有效样本量。不用七条最高 mAP 选版本，不把胜负增多当作正确率提高。

| 结果 | 后续决定 |
|---|---|
| CPU 来源一致性、容量或兼容性失败 | 停止 GPU 比较，修复独立接口 |
| B 相对 A 引入非法引用、技术回退或审阅确认的新错误 | 紧凑格式不晋级；检查解读歧义，建立新版本后再验证 |
| C 没增加旧证据、没有恢复有用判断，或只保留了重复内容 | 停止该记忆分支，不自动试更多权重/容量 |
| C 的变化依赖已知错误事实，或新增无依据胜负 | 记忆保留不能算精度成功，转入内容可靠性诊断 |
| C 确有可追溯的旧证据补回及判断修正，未发现新增错误 | 仅保留为待确认机制；先过内容质量关，再考虑 100 条开发复核 |

已知错误观察仍留在 A/B/C，因此即使 C 的 mAP 提高，也不能据此批准错误观察器上线。七条中未发现错误同样不等于证明安全或无退化。未被独立复核的语义判断在结论中明确保留不确定性。

## 7. 后续分支：观察内容、100 条与完整 Agent

### P2：按证据类型修复观察，独立于记忆对照

继续利用已有 201 个固定审阅帧次及其原窗口，先完成无需推理的错误分类：跨镜头归属、物体/身份误识别、句子字段截断、动作/结果证据缺失。已知错误帧保留为回归案例，不能把这些案例的修复率当整体准确率。

身份、物体、场景疑问才考虑选择性单帧核查；动作、事件结果、反应变化使用短时连续片段，并保留发生过程和前后关系。不能仅缩成 2 秒或复制单帧就声称验证了动作。窗口须由问题与源时间确定，不能由 GT 高光边界确定。

下一次观察探针只能选择上述一种错误类型，固定问题和输入比较两个观察条件；必要的输出字段修复单列，不能同时换记忆顺序、比较提示和观察分组。具体清单、绝对预算及内容判据在 P1 结论后另行冻结，**本计划没有把一整轮新观察或 672 次逐帧重跑加入当前队列**。

进入 100 条前，须用拟正式使用的自动观察器复验固定 28 窗口/14 视图，审阅全部进入活动记忆的新事实，并保留已知错误帧与预选一般样本；报告支持/矛盾/无法判断和句子完整性。已知场景错配、无依据动作或结果不能继续作为可引用事实；对改变决策所依赖的证据逐项回源核对。不能按 GT 手工挑选正确事实，不能把 672 次结构通过代替内容验收。

若动作依据仍缺失，则保持未决，不以静态描述补造结果。观察内容改变后，锁定的记忆版本须在同七条做一次单独冻结的小规模复核，不能沿用旧噪声事实上的结果；这仍是开发复核，不是未见测试。该观察与复核工作另立预算，不挤入本轮 840 次。独立人工核验未完成时不宣称语义准确率或观察质量已获独立确认。

### P3：有条件重跑原 100 条

只有机制和内容核验支持改动，才冻结一个版本进入原开发 100 条。保留 B0、E0、C_direct4、E_memory、E_uniform、E_targeted 及预算配平；若仅更新记忆表示，未受影响请求严格复用。该集合用于开发，不能称未见确认集。

保持既定精度门槛：E_targeted 的 VeryGood mAP 比 E0 / C_direct4 / E_memory / E_uniform 中最强者至少高 **1 pp**，Hit@1 最多下降 **1 pp**，技术回退不超过 **1/100** 且不高于有效父条件，并有真实配对观察。9,200 次冷启动 Agent 请求、6 GPU 小时和端到端 token ≤6×B0 的历史上限继续约束，但新增设计必须重新逐项核算、冻结绝对 token 预算；不能直接沿用旧调用公式。

失败则停在开发结论，不降低门槛、不自动扩到全量。通过后才核验独立确认集的历史使用和源视频重叠；已查看的 val1550 不称未见集。

### R3 与跨数据集顺序

R3 的接口与 CPU 夹具可继续完善。真实 F_once / F_loop 的 A/B/C/D 功能验收另建协议，验收事件归属、定向观察、边界调整、数量/时长和 partial/abstain；它可作为功能工作独立推进，但不能绕过 R2 的精度失败去扩大性能实验。

局部证据可靠性与真实闭环明确后，优先小规模 SVHighlights 验证长视频事件过程和边界。QFVS 暂不再次全量密集评分；MR.HiSum、TVSum 在适配任务和开发清单冻结后再迁移；TVHighlights 数据未就绪，暂不列队。
