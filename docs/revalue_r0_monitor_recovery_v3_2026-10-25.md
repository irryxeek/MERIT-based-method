# ReVALUE R0 监测兼容性修复补充 v3（2026-10-25）

## 已发生问题

[工程修复协议 v2](revalue_r0_repair_protocol_v2_2026-10-25.md)在模型加载后、首个新请求生成前退出。新增的显存监测通过 Python 函数调用 vLLM worker RPC；本地 vLLM 0.12 默认禁止对此函数进行序列化。该工程错误与模型推理质量无关，原始响应、失败源码、绑定与账本全部保留。

v2 实际运行 37.4860 秒，新增一个预留请求，尚未生成模型输出。该失败仍保守计为一次尝试、1,754 token；与 v1 合计 **301 次尝试、557,588 token、2,600.3614 秒活动 GPU 时间、三次 worker 启动**。

## 修复与唯一预算变更

v3 以进程外 NVML 驱动计数代替模型进程 RPC，记录调用前后设备显存快照。监测错误只作为诊断值保存，不得中止模型生成。这些快照不是推理瞬时峰值；不启用宽松序列化开关。

为修复这次由新增监测造成的生成前退出，**R0 worker 启动上限由三次补为四次，仅增加一次启动**；代码核验该例外只适用于冻结 v2 的这一个序列化错误，已有模型输出的请求不能使用该例外。R1 启动上限仍为三次。

R0 的 **500 次累计尝试、7,200 秒活动 GPU 时间上限均不变**；历史成本不清零。v3 计划新增 140 次比较/回看，累计计划 441 次，剩余最多 59 次瞬时故障请求余量；只有一次 worker 启动机会，剩余活动时间 4,599.6386 秒。额度未用完也不得绕过启动门槛反复尝试。

## 其他协议与验收

沿用 v2 已冻结的紧凑比较/回看提示、schema、KV 缓存、上下文、模型、原 20 条样本和原始帧。160 个共享依赖仍从经过哈希验证的原始成功响应复用；v2 尚未执行到的依赖从其冻结索引继承，每次使用仍校验请求和响应。

CPU 增加监测失败不影响合法生成、NVML 不可用时降级、该启动例外不能用于已有模型输出的回归检查。随后在新目录 `revalue_r01_v3_2026-10-25` 运行原 20 条；全部通过才放行 R1。其余 R1 调用和 token 预算、停止条件及 R2/R3 范围均遵守[原方案 v3](revalue_execution_plan_v3_2026-10-23.md)。本补充不以准确率为依据调整提示或替换样本。
