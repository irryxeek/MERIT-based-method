## 本轮顺序与停止点

先执行 P0 CPU 编码、容量和兼容性实验，同时整理观察内容问题。**观察内容审查前置于 GPU 比较**：原 79 条观察事实只用于本轮容量诊断；已知错误不能因为编码通过而进入新的精度实验。

P0 任一硬门槛失败即保存负结果，停止 A/B/C 比较。P0 通过后，另行冻结针对一种观察错误的修复探针、输入清单及绝对预算。修复后的同一事实集用于 A/B/C，避免先对错误事实做 840 次比较后再重复推理。没有自动启动 100 条、全量、R3 或跨数据集任务。

## 固定输入与三个视图

父运行：`$ZEROSHOT_ARTIFACT_ROOT/revalue_frame_grounding_v1_2026-10-26/`；原预测来自 `revalue_r2_v3_2026-10-26/`。

干预 qid：5172、881、9841、7971、2973、3478、1129。每条均匀/定向两臂，合计 14 视图。原 R1 20 条与七条干预的并集为 23 条，另外 16 条仅核验无观察路径，精确复用已有结果。不得按标签选样。

| 视图 | 固定内容 | CPU 检查 |
|---|---|---|
| A | 已冻结 `scoped_memory` 的完整来源和 S0 | 与父视图哈希一致 |

C 只用原 E_memory 的活动 items，按 `(不含观察锚点, 最小锚点, 排序后 fact_ids, 原下标)` 排序。已有 ID 不重复；放不下则跳过继续；不得改写、拆分条目或重新编号已有表项。未知项单列，不能冒充可见证据。

## 硬门槛与计量

采用父运行同一 Qwen3-VL tokenizer，`add_special_tokens=False`，对紧凑 JSON 的**全部模型可见字段、来源表和图例**计数，容量仍为 1,024 token。浮点时间不舍入，未核验状态不省略；不能靠后台隐藏表解码。

1. 14/14 B 可精确还原 A，引用许可一致；全部来源通过现有校验。
2. 每份 B 不长于 A；B、C 均不超过 1,024 token。
3. 至少 7/14 份 C 能追加至少一个含非 unknown 事实的完整旧条目。
4. 16 条未触发路径的输入、缓存绑定和预测保持一致。
5. 回归测试拒绝来源篡改、帧错配和伪造候选；追加不能改变已有来源索引。

报告逐视图 token、文本/元数据开销、旧事实与非 unknown 保留量、候选覆盖及来源作用域。14 视图并非 14 个独立视频，容量成功不等于 HD 精度提高。若某项失败，记录具体失败，不通过改写事实、扩大容量或更换样本使其过关。
