## 3. 唯一因素与固定条件

**因素：一次请求的判断目标范围，`whole_table → one_designated_interval`。**

主要控制为已经完成的**显式时间键整表 QV20**，直接按固定目标索引读取其旧分数，新增控制调用为 0。原位置数组 Direct 仅作历史参照，不把“原数组→新单目标”的差异解释为纯粒度效应。

固定原全部 QV20、顺序、query、视频持续时间、64 帧像素及顺序、真实 PTS、metadata、视觉网格、原生时间合并、SYSTEM、任务定义与评分含义。保持 Qwen3-VL-8B-Instruct BF16，revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`，原 Direct 引擎、temperature=0、top_p=1、top_k=-1、seed=0、context=8,192、max output=2,048。

每次仍输入整视频的全部原 64 帧；不重采样、裁剪、重排序、突出显示帧、追加局部图或补证。请求相互独立，不将另一目标的结果或旧控制分数送入提示。一个视频的两个请求会重复呈现同一组帧；这不等于总输入成本相同。

## 4. 在看标签和选择控制分数前冻结目标

规则只依赖原网格长度 `N=floor(duration/2)`：

```text
early_index = floor(N / 4)
late_index  = floor(3N / 4)
target interval = [2*index, 2*index+2) seconds
```

## 5. 提示、schema 与导出

仅替换原时间键提示中的两个范围相关段落，其余文字、chat 模板及视觉占位符逐字相同。75 格、early 目标的实际例子：

```text
Give a highlight score only for interval index 18, [36,38) seconds, within the 75 consecutive 2-second intervals.
```

原 `Index 0 covers...` 网格定义、query 和 0–100 含义保留；原“为每个片段评分”被上述单目标指令替换，避免同时要求整表与单项。

```text
Return only a JSON object with a single key "scores" containing an object with exactly 1 entry. Use the target interval's start and end times in seconds as its key: "36-38". This key denotes [start,end), and its value is that interval's integer score. Include only this interval. Do not include explanations or additional keys.
```

schema 只允许 `scores` 下一个预定时间键、整数 0–100，禁止额外键。示例 `{"scores":{"36-38":80}}` 只是格式示意，不注入固定示例分值。仍使用原紧凑 xgrammar 语法，允许 0、50、80、100 等合法值以及两目标同分。

导出返回 `(qid, target_id, clip_index, interval_key, score)` 的稀疏记录。错目标、额外/重复键、数组、非法值或截断均为失败；不修补、不填零、不插值、不回退旧分数、不复制到其他时间格，不导出完整 `pred_saliency_scores`。

## 6. 可支持和不能支持的结论

预先规定的主读数为 20 对固定目标的 `early_score − late_score`、异值对数、相同对数、有效对数及完整 40 目标状态。另列每个新分数与其冻结整表控制分数之差；控制投影是旧预测索引操作，不是新模型预测。

- 两目标不同，只支持“在这些指定位置、当前输出范围条件下出现了非恒定响应”。它也可能受目标位置先验或提示敏感性影响，不能直接证明使用了正确视觉时序证据。
- 两目标相同，是合法负结果；不能外推所有其他时间位置相同，也不能证明模型完全没有时间理解。两个目标可能本来就同样重要，输入也可能未覆盖决定性动作。
- 两目标统一偏离控制，只表明整体评分发生变化，不计为时间区分改善。
- 本协议不加载 GT，不计算新 mAP/Hit@1、目标子集 AP 或边界精度；不把 40 个分数拼成全网格，不报告虚假的全 20 性能。

不可避免的共同变化包括目标限定文字、注意力聚焦、输出项数与长度、生成位置/依赖、调用数和重复输入成本。这是**目标范围方案**的机制诊断，不是纯时间语义、纯生成长度或精度收益的因果实验。不得声称控制了这些因素各自的独立作用。

完整可判读门槛是 40/40 有效、20/20 对完整且所有来源契约通过。至少一对异值只记为探索性机制信号，不构成准确性门槛通过，更不放宽原价值/Agent 模块门槛。

## 7. 全分母与停止规则

40 个目标及 20 对均保留。单目标失败、缺失或未尝试都写明状态，分数为缺失，不能记为 0 或并列。只有两个目标都有效，才计算该视频的差分。

技术不完整时，整体机制结论标为未完成；可列有效目标和有效对的描述，必须同时显示完整 40/20 分母，不能用成功子集代替完整结果。异值对数量附缺失对数；不将缺失对算作同分。

未来遇到首个输入/源哈希漂移、实际多模态 token 与冻结哈希不符、上下文超限、格式/导出错误、OOM、服务异常、worker 异常退出或任一预算达到上限，都停止全轮，保留失败与未尝试记录。失败 token 不可知时按该请求完整输入＋输出预留记账。不得重试、降帧、改提示、换模型、替换目标或追加 smoke。

## 8. 新 CPU 检查与上下文预算

本轮仅运行新稀疏目标契约：5 项单元测试通过，24 个新单键语法案例和 4 条实际 Qwen 词表 token-mask 路径通过；Ruff 通过。合成输出全部标记为 CPU fixture，不是模型预测。

40 个准备请求只改变 `prompt/output_schema/grammar_sha256`；独立 `target_id` 用于将来记账，原 query 的 `row_key` 保持不变。实际目标范围以冻结 manifest 为准。

- 新 prompt 为 **4,625–5,149 token**，相对对应整表控制少 4 或 8 token。
- 保留 2,048 输出上限，最大上下文预留 **7,197/8,192**。
- 40 次重复输入共 **204,414 token**；含输出上限的全额预留 **286,334 token**。
- 合法单目标合成输出为 11–15 token（不含终止 token）；实际输出和耗时尚未测量。不能只看单次输出变短就宣称总成本降低。
- 沿用旧已验证的时间戳展开函数，只计算新 prompt 预算；未重复旧 prompt 测试、采样覆盖或源帧诊断。

CPU 进程使用本地 tokenizer/语法库，拦截网络连接、子进程、推理 API 导入、权重、视频、帧数组和 GT 读取；CUDA 未初始化。tokenizer 算术计数不记为实验 token 消耗。

## 9. 未来独立预算建议，尚未授权

| 项目 | 新单目标诊断建议上限 |
|---|---:|
| 正式请求／总尝试 | 40／40 |
| 故障额外调用／重试／smoke／新控制调用 | 0／0／0／0 |
| 绝对输入＋输出 token | **327,680** |
| 当前固定请求全额预留 | 286,334 |
| 最大同时 GPU 数 | 1 |
| 计划 worker 启动／GPU worker 分配次数 | 2／2，顺序执行 |
| 每 worker 请求上限 | 20：固定 10 条 query × 2 目标 |
| 每 worker／全轮 GPU 生命周期 | **900／1,800 秒** |

预先分片：worker 1 为原序前 10 条，worker 2 为后 10 条；各自按 early→late 执行。第二个 worker 只能在第一个完整成功、所属进程退出且全轮额度充足时启动；不重启失败 worker，不共享历史对话，不修改引擎或编码缓存参数。

该分片复用已知长队列 OOM 风险的旧诊断，避免把本轮准备变成新的缓存试验；**20 请求分片不构成无 OOM 保证**。两个预定冷启动会增加成本，必须记录；这也是相对旧整表单 worker 的运行安排差异，不能拿时延比作纯输出长度效应。

每个生命周期包含启动、加载、推理、退出与清理，末尾预留 20 秒；总计不超过 1,800 秒。只可使用匹配型号的空闲 GPU，记录实际 UUID；无资源则不启动，也不无限排队。所有失败启动都占 worker 名额。当前没有 GPU 运行器、启动命令或已选 GPU。

以上均为 `execution_authorized=false` 的建议。将来需要用户明确批准新 40 次、327,680 token、顺序两 worker/最多同时一卡及生命周期上限，之后仍须实现并审查匹配运行器、冻结源码和授权收据。**不重新申请已解决的时间键 20 次额度，也不从任何旧账本转移余额。**
