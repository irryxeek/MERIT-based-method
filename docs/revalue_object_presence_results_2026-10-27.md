## 2. 做了什么

从此前固定图像中选择 **15 张、七条 query**，每图两个问题，共 30 题。三例历史困难对象为手机、狗、jet bridge；同时加入清晰正例、清晰反例和模糊对照。协作助手逐张看图，在推理前冻结 **14 个 supported、10 个 contradicted、6 个 cannot_determine** 参考标签。父代理实现运行器、检查来源、执行和审阅输出，另一协作代理只读审查启动代码。

每题运行两臂：

- **direct**：明确三态定义，直接核查指定区域中的物体存在性。
- **evidence_first**：在相同提示中增加检查轮廓/部件、区分手/阴影/水花/背景、避免从姿势和场景猜测的要求。

两臂共享像素、PTS、Qwen3-VL-8B-Instruct 权重、BF16、temperature 0、JSON 字段及 160 output token 上限；交替执行顺序，答案互不可见。模型只看到物体、区域和待核查断言，未见旧 caption、参考标签/理由、选样分组或高光 GT。所有请求新增，无重试。

这是**预先人工构造问题的静态核查探针**，尚未自动生成证据缺口、选择回看位置或调用 Agent 工具。两次相同图像仅用于视频编码器兼容，不能提供动作或前后变化证据。参考标签属于助手判断，既不是人工真值，也不是独立跨模型评估；已知错误和普通对象均为刻意选取的开发案例。

手机从旧广泛描述中的错误断言变为正确否定，是一个有用案例；但新任务同时改为指定区域的物体问题及新输出契约，不能把这项变化单独归功于 evidence_first。两个新臂完全相同，未证明额外核查提示带来判断收益。

## 4. 为什么没有晋级

预定机械条件中，完整性、正例保留和“不劣于 direct”通过；**三个困难对象均不得被错误肯定**这一条件失败。父代理逐张检查全部 15 张图、阅读全部 60 份解释，另发现部分证据只是复述区域，以及“湿毛”、未确定食物细节等额外断言。仅有合法 JSON、来源哈希和正确状态选项，不足以构成可入库的事实。

本轮还检查了“不确定选项是否被解码器屏蔽”这一具体疑点：

- 在 CPU 上，用本地实际 tokenizer 与本轮相同 compact EBNF，对三个合法状态逐 token 检查语法接受和 bitmask；**三个状态均可生成**，非法状态被拒绝。
- 诊断 grammar 哈希与 60 次请求全部一致；未初始化 CUDA、未新增模型调用。
- 最大实际输出仅 **59 token**，全部 `finish_reason=stop`；没有达到 160 token 截断上限。

这些检查排除了本次测试中“状态枚举不可达”和“输出被截断”的解释；不代表对全部解码行为的形式证明。结合解释中承认模糊却仍作确定判断的现象，当前更需要验证证据是否足够、如何处理无法辨认，而非继续增加同类提示文字。

## 6. 下一步建议

**先测试增加针对性的视觉信息，停止重复仅加长核查提示。** 可保留这 30 题及参考标签，冻结原始视频帧上的 ROI；两臂分别给“全图＋全图重复对照”和“全图＋原始分辨率局部裁剪”。两臂使用同一核查提示、同样展示帧数和预算上限，仅第二路画面内容不同，成本据实记录。这里应回读原始像素，不能仅把已有低分辨率图放大后称为新增细节。

该设计仍是开发诊断，裁剪区域必须在新输出产生前固定，不根据答案调整。保留清晰正反例，既检查细节是否补足，也检查局部视野是否引入新错误。源帧本来模糊或被遮挡时，裁剪可能无效；无法补证的对象应允许继续 unknown，不能强制出确定答案。

后续再单独验证可辨识性字段和入库条件是否有用，并用短时连续输入处理动作、反应变化及结果问题。不同改动分开对照。观察器只有通过原固定 28 窗口与全部拟入库事实审查，才回到统一事实集上的 A/B/C 记忆比较；本轮未自动继续任何 GPU 任务。
