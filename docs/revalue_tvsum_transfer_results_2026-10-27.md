## 2. 测试设置和评价口径

复用已完成 TVSum B0 缓存，使用固定 UMT val10 划分、原 Top-5 候选及每候选至多四张 B0 已见帧。权重为 Qwen3-VL-8B-Instruct，BF16、temperature 0；输入保持 `Highlight of this video.`，没有标题、类别、音频或参考标签。事实提取与记忆构建不读取 query。四组如下：

| 条件 | 内容 |
|---|---|
| B0 | 原 REZE 初始化分数，核验后复用 |
| P_pair | 原 Yes/No 双向成对比较，依据概率与双向支持规则置换候选分数 |
| C_direct4 | 任务解析＋原帧四态比较，无记忆 |
| E_memory | 同一任务解析＋五候选事实＋决策记忆＋原帧四态比较 |

E_memory 比较时仍看旧帧，是“图像＋记忆”，不是纯文本记忆评分。活动记忆含来源最多 1,024 token、生成草稿至多 12 项。本轮无新观察，也未运行完整 Agent 的回看、事件选择和边界细化。P_pair 的提示和排序复用原实现，但统一部署于 ReVALUE 单请求引擎，不能宣称与历史批处理部署逐位或吞吐一致。

主指标为 **TVSum UMT Top-5 mAP**：在官方 2 秒网格上，逐标注者按其评分中位数二值化，以原生 Top-5 梯形 AP 计算，再平均标注者和视频。它不是摘要 F1，也不能与 QV 的 VeryGood mAP 直接横比。完整预测先冻结，再读取标签；四组均通过原生评价器与独立实现的一致性核对，B0 重现此前 **61.32**。

## 4. 为什么四态比较没有提升

### 4.1 通用任务被解析出错误的对象约束

十条视频的 TaskSpec 完全相同：`request_type=generic`，同时将 `Highlight of this video` 提取为一个 `object` 约束。原文没有指定具体对象。现有校验只证明引用确实来自 query，不能证明它在语义上是对象约束。

| 诊断 | C_direct4 | E_memory |
|---|---:|---:|
| 有向比较 | 200 | 200 |
| a_better / b_better | **0 / 0** | **0 / 0** |
| tie | 190 | 183 |
| insufficient | 10 | 17 |
| 双向配对后 tie／未决／胜负 | 91／9／0 | 86／14／0 |
| eligibility 为 satisfied／unknown | 0／400 | 88／312 |
| A/B 交换后资格判定不一致的无序对 | 0/100 | 28/100 |

排名器没有收到胜负边，因而保留 B0。模型产生的是有效 tie/insufficient，不是解析失败后的技术回退。带记忆后增加了一些“满足约束”的判断，却没有增加偏好；也出现了资格判定随 A/B 顺序改变的情况。当前证据指向任务解析、比较标准和证据使用仍需适配，尚不能单独归因于记忆或视频时长。

### 4.2 记忆大量丢失不确定性，且可能传播错误事实

共生成 **448 条事实记录（含 185 条 unknown）**，活动记忆保留 **130 条（含 9 条 unknown）**。事实总数包含未知项，不能全部称为已观察到的事实。两条抽查视频各有 45 条记录，均只保留 12 条；其 17、22 条 unknown 全部丢失，记忆为 785、946 token，且没有 token 容量驱逐。因此这两条的主要损失不是 1,024 token 事后截断，至多 12 项的草稿限制和模型筛选仍可能影响保留。

对每个分片最先完成的视频进行只读助手抽查，未读取高光标签：

- **自行车样本 JgHubY5Vw3Y，候选 53**：帧 `s3176/s3191/s3206/s3221` 显示车锁、手和钥匙，事实却写成“调整后拨链器”和“链条运动”。两条描述均被记忆保留，随后进入比较理由。这是错误观察经记忆继续传播的具体案例。
- **理由与结构化引用不一致**：自行车 53→51 的理由将 B 写成候选 52 的事实；舞蹈样本 12→19 的理由将 B 写成候选 18 的事实。结构化引用合法不代表自由文本理由没有错配。
- **动作差异被概括掉**：舞蹈记忆保留衣着和场景，却删除候选 13 的动作变化描述。图像可见起跳变化，但这不证明该片段在官方标注中应排第一。

上述为**共享上下文助手抽查，不是独立人工真值**；仅覆盖两条视频，不能据此估计总体事实错误率。发现问题后没有修改本轮提示、候选或预测。

## 5. 成本与工程核验

初始化缓存中的十视频正式请求合计 **1,260 次、894,125 token、7,537 帧次**，本轮复用而未重新执行。下面“含初始化”只加入这些逐视频正式开销，原 B0 共享 smoke、失败尝试等历史开销未纳入。

| 方法 | 新增请求 | 新增 token | 含正式初始化 token | 相对 B0 正式 token |
|---|---:|---:|---:|---:|
| B0 | 0 | 0 | 894,125 | 1.000× |
| P_pair | 200 | 195,600 | 1,089,725 | 1.219× |
| C_direct4 | 210 | 321,616 | 1,215,741 | 1.360× |
| E_memory | 270 | 591,526 | 1,485,651 | 1.662× |

C/E 的独立方法成本均计入任务解析；实际联合执行只做一次。因共享 10 次任务解析、1,810 token，三列相加与实际新增总量不同：本轮实际为 **670 次、1,106,932 token**（输入 1,036,169，输出 70,763）。E_memory 比 C_direct4 多 **269,910 token**，本轮没有对应指标收益；没有 P_pair 回退依赖成本。

- 两卡生命周期合计 **2,102.26 秒（0.584 GPU 小时）**，包含模型加载、等待监督器轮询及清理。不能拿该值与缓存中的纯推理计时直接比较加速比。
- 新请求共展示 **5,000 帧次**，全部来自 B0 已见帧，没有新源时刻；多次展示仍计入开销。
- 670 次均完成；P_pair 的 200 次 `finish_reason=length` 是预设只生成一个判定 token，另 470 次 JSON 输出均正常停止。
- 最大单请求输入＋输出预留 **3,799 token**，低于 6,144；总 token 和双卡时间均在冻结预算内。
- 启动前 **18 项 CPU 测试通过，Ruff 通过**。独立代码审查后修复父文件收据、信号清理、超时边界和结果重放核验，修复版本才启动。
- 112 个冻结来源文件、25 个冻结输入文件哈希一致；完成记录、原始请求收据及排名重放通过。两个分片退出码均为 0，无本运行残留进程，GPU 6、7 回到空闲。

## 6. 下一步判断

**先修复通用高光任务的决策契约，再扩大现有四态比较和记忆方案。** 当前跨数据集测试已经识别出一个比“换数据集继续跑”更具体的问题：比较器可以生成合法解释，却几乎不作排序决定。

建议下一轮保持相同候选和旧帧，先单独对照：原 TaskSpec 与“无具体 query 时不添加对象约束”的 TaskSpec；冻结其它比较、记忆及排名设置。该十条继续作为开发诊断，不能包装成未见验证。若仍退化为 tie，再分别检验通用重要性比较标准与细节证据保留，避免一次改变多个因素后无法归因。

记忆修订应保留动作差异、未知条件及源事实，检查比较理由和结构化引用的一致性；其收益仍需 E_memory−C_direct4 的同设置对照。新的 ROI/连续帧观察是另一变量，不能混入本轮旧帧迁移结果。P_pair 在 QV 的正收益未直接迁移到 TVSum，需要单独验证通用重要性标准，不能宣称重排普遍有效。

SVHighlights 七场缓存仍可用于下一阶段长视频试验，但在启动新四态比较前应先验收通用任务解析和非退化决策。MR.HiSum 的排序与摘要选片需分开评价，QFVS 的双概念查询另设适配。本轮没有自动扩大数据集或降低原 QV 门槛。
