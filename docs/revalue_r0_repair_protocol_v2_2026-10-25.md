# ReVALUE R0 工程修复协议 v2（2026-10-25）

## 目标与触发原因

这是[执行方案 v3](revalue_execution_plan_v3_2026-10-23.md)的工程修复补充。v1 已保留全部 20 条记录，16 条完全通过；3 次回看输出在 512 token 截断，1 次比较漏掉 A 侧引用，另有一次 24 帧推理显存溢出。R0 未计算高光指标，R1 尚未启动。修复不根据准确率选择提示。

## 冻结内容和改动

固定原 20 条 query、C0 Top-5、候选旧帧和回看 24 张新帧，重解码核验像素与 PTS，沿用 Qwen3-VL-8B-Instruct BF16、temperature 0、原输出 token 上限和评价协议。

1. 比较和回看采用紧凑 JSON grammar，删除结构缩进造成的 token 开销。比较的结构约束要求胜负或平局引用双方证据；证据不足仍可输出 `insufficient`，未观察清楚仍可为 `unknown`。
2. 回看最多六条事实，每条描述不超过 96 字符、最多四个来源 ID；最多三条待核实问题，每条不超过 64 字符。提示使用简短英文，不复述来源 ID 已映射的时间戳、衣着或场景冗余。保留完整源帧与 PTS 日志，不强制生成赢家或完整结论。
3. 显式 KV 缓存由 2 GiB 调至 1 GiB，最大上下文 6,144 token，prefill 批量 1,024 token；逐调用预留前检查展开输入和输出上限。v1 实际最大输入 3,387 token，小于新上限。启用可扩展分配段并记录每次 GPU 分配峰值和余量。输入帧数量、像素、分辨率保持一致。

## 复用与累计预算

TaskSpec、事实和两类记忆的提示、schema、帧、输出限制均未修改。仅复用这 160 次已成功的共享请求；每次校验原文件 SHA256、响应摘要、完整请求内容和语义约束。复用失败即停止，不静默重生成。所有比较与回看按新协议重做，计划新增 120 + 20 = **140 次调用**。

v1 的 **300 次尝试、555,834 token、2,562.8754 秒活动 GPU 时间、两次 worker 启动**计入累计账本。R0 总上限仍为 500 次尝试、7,200 秒、三次 worker 启动；v2 因而最多新增 200 次尝试，计划 140 次，至多剩余一次 worker 启动和 4,637.1246 秒。复用不重复收费，但历史失败开销保留。

## 验收与后续

先通过 CPU 回归检查，再执行原 20 条 GPU 验证。所有共享请求、三组双向比较及 24 帧观察均通过，且未超预算，才冻结新正式协议并启动 R1。格式失败不进行同版本语义重试，不能替换样本或重置资源上限。

R1 仍为 E0、C_direct4、M_plain、M_decision 四条件，最多 1,360 次正式新调用和 68 次瞬时故障追加尝试，各方法遵守原 6 倍 B0 token 上限。R1 重新生成其共享请求，不把 R0 工程响应算作正式新推理；R2/R3 不自动启动。工程通过不等于高光指标改善或人工语义审阅通过。

v1 全部源码、输入、原始响应、失败和账本保留。v2 使用新运行目录、源码快照和绑定文件；修复结果另写报告，不回写本冻结协议。
