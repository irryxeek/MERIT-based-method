## 已实现的修复

| 问题 | 修复 | 仍保留的约束 |
|---|---|---|
| `links` 嵌套错误、缺字段、空白输出耗尽 | JSON Schema 约束解码，关闭任意结构空白 | 不接受截断输出；不提高 8,192 token 上限 |
| 重复生成固定时间、编号、维度名 | 程序根据冻结单元生成元数据，模型按单元 ID 和 cue 名返回观察 | 仍需要模型明确提供描述与 cue 的图片引用 |
| cue 超长、错误只给笼统提示 | 校验指出字段路径、实际长度、允许图片与事件 ID | cue 上限仍为 160 字符 |
| 整段重试重复相同错误 | 最多一次字段补丁，只允许替换失败路径，其他字段冻结 | 初始 JSON 无法解析时才重新生成完整对象 |
| cue 引用邻居图片或不可用上下文 | 解码限制允许 ID，程序再次检查；重试仍失败则该 cue 变为 unknown | 不编造引用，不把 unknown 当作 0 强度 |
| 一个窗口失败导致整条 query 回退 | 继续处理其余窗口，仅失败窗口保留 D0 | E1 整体失败时整条保留 D0 |

程序最终降级的 cue 使用 `level=null`、空图片/上下文引用，保留原值、失败路径、原因和
`cue_to_unknown` 标记。描述或描述引用仍不合法时，整个窗口失败，不伪造观察。
无效可选图边继续剔除并记账。结构和引用通过不代表观察内容已经人工验证。

## 固定条件与失败统计

- 原 20 条样本、14 条有效候选、每条 3 个窗口，共 42 个窗口/组。
- 与前轮逐文件核对，20 份推理输入哈希完全相同；当前图片、顺序、时间戳和前两个窗口上下文保持固定。
- C10 每 10s 一条观察；F2 每 2s 一条观察；每个 10s 窗口仍只有原来的 5 张图片。
- 两组共同使用 Qwen3-VL-8B-Instruct、BF16、TP=2、temperature=0、seed=42。
- 每组计划 42 次建库、14 次 E1；建库上限 8,192 token，E1 1,024，最多一次格式修复和一次传输重试。
- E1 仍接收全部固定候选帧、原查询和同一个评分提示词；若有窗口失败，程序仅合并成功窗口的分数。
- 不新增抽帧、不重选候选、不运行 E2/E3、不扩大样本或启用新的验证集。

报告分别统计：首次通过、修复后通过、cue 降级、可选边剔除、窗口失败、完整记忆覆盖和 E1 完成。
`partial` 不等于所有字段均正常生成；6 条继承无候选不算新增建库失败。
