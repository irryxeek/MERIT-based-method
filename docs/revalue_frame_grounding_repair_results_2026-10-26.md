# ReVALUE 来源绑定修复与单帧观察验证结果

日期：2026-10-26。**已修复来源时间丢失、片外事实直接归属候选、标点描述进入事实库三个工程问题，并完成 672 次同源画面验证。固定错误帧的跨场景描述得到纠正，但视觉细节误判、记忆容量和成本问题仍在；本轮不把单帧观察器替换进正式评分。**

执行依据：[冻结协议](revalue_frame_grounding_repair_protocol_2026-10-26.md)、[上一轮观察诊断](revalue_r2_observation_probe_results_2026-10-26.md)。没有新增 HD 指标，未改历史预测，未运行新 100 条 R2 或 R3/R4。

## 1. 实际代码修复

| 问题 | 修复 | 验证边界 |
|---|---|---|
| 观察事实只有帧 ID，没有完整时间 | 后端从真实源帧写入 PTS、目标区间、片内/片外/跨界关系，活动记忆保留这些字段 | 时间来源正确不等于描述正确 |
| 片外内容被挂到观察锚点名下 | 仅完整位于目标内的事实可直接归属候选；其他事实保留锚点，但 `candidate=null`；比较引用校验拒绝将其直接用于目标 | 片内时间也不能证明属于同一完整事件；比较器语义仍需单独验证 |
| 多镜头描述与帧 ID 对不上 | 独立单帧观察，不让模型选择帧 ID；代码将描述绑定到唯一输入帧 | 单帧不能验证动作过程、结果或前后关系 |
| 空内容被误当事实 | 新增确定性过滤，只有标点的 `visible` 不再形成可引用事实，保留原响应与不确定项 | 这是空内容过滤，不是语义正确性判定 |

核心实现为 `evidence_grounding.py`、`frame_observer.py`，并接入 `memory.py`、`comparison.py`、`r2_planner.py`、`r2_worker.py`。新的 R2 绑定可显式启用 `evidence_interface: temporal_v1`；旧源码快照和默认历史路径保留。单帧观察通过独立运行器验证，尚未替换正式 R2 的观察内容生成。

## 2. 来源接口的 CPU 对照

固定原七条实际回看样本及全部原始描述，不新增模型调用：

- **14/14 份旧活动记忆重放完全一致**，说明兼容路径未意外改变原结果。
- 原 79 条观察事实中，57 条引用全在目标内、16 条全在片外、6 条跨界。新接口取消后两类的直接候选归属；这些数字不是事实错误率。
- 新时间字段被计入原 1,024-token 限额，14 份视图均未超限；片外事实不能通过候选引用校验。
- 保持原“新事实优先”策略时，14 份视图的旧事实引用淘汰总计由 **81 增至 167**。按视图计数，不是去重后的独立事实数。

这项容量对照使用原 79 条描述，**没有将全部新单帧描述写入正式记忆**。它说明来源字段不能不计成本地堆入活动记忆，后续须独立验证紧凑表示与关键旧证据保留。

## 3. 单帧验证规模与成本

固定原七条 query、28 组观察、候选和源像素。每次将一张源帧复制成两张，适配现有视频编码器；不额外读取新的时刻。模型仍为原 Qwen3-VL-8B-Instruct 权重，温度为 0。

| 项目 | 上轮中性窗口描述 | 本轮逐帧描述 |
|---|---:|---:|
| 模型调用 | 28 | 672 |
| 源帧次 | 672 | 672 |
| 模型展示帧，含复制 | 672 | 1,344 |
| 输入 token | 93,594 | 221,861 |
| 输出 token | 6,626 | 35,879 |
| 总 token | 100,220 | **257,740** |
| 累计 GPU 秒 | 282.45988 | **1,389.27365** |

本轮 672 个源帧次对应 671 个不同的 `(qid, 源帧)`，不将帧次冒充去重数量。28 组观察及其帧集合保持一致，但提示、输出结构和输入分组改变，因此这是一项组合修复，不是只改提示的单因素实验。

GPU 4、6 于北京时间 **16:06:44** 启动，分别在 **16:21:00、16:15:38** 退出。墙钟约 **14 分 16 秒**，累计 **0.38591 GPU 小时**，包含服务启动和清理；两卡均已释放。总 token 为上轮的 **2.57 倍**，累计 GPU 时间为 **4.92 倍**，不能称为效率改进。所有历史费用另行保留。

672/672 响应通过结构和来源技术检查，新增请求 672、追加尝试 0；该完成率不表示事实正确率。

## 4. 固定样例审阅

按冻结规则选取 **201 个帧次、14 张对照图**，覆盖全部七条样本。下列七个此前已记录错误的源帧，在助手核对中改为与当前场景一致的描述：

| 样本与帧 | 新描述对应的可见内容 | 原错误 |
|---|---|---|
| 1129：s1122、s1214 | 淋浴地面上的脚/小腿 | 沿用前一镜头的“手放颈部” |
| 1129：s1410 | 室内穿黑色帽衫的女子 | 仍写成淋浴动作 |
| 1129：s1461 | 机场停放的飞机 | 仍写成踩淋浴地漏 |
| 881：s2513 | 夜间泳池中的人物 | 把飞机画面的文字绑定到泳池帧 |
| 5172：s1291 | 室内女子 | 描述成泳池场景 |
| 9841：s2197 | 户外穿西装的男子 | 混入后一镜头的视频通话人物 |

7971 的广场行人与后面的绿衣女子也能分别描述，2973 的柜台/手部与后面的持餐盘儿童不再一概混写。3478 的部分模糊浪花帧返回不确定，不能当作观察失败后偷偷补生成。

**仍发现普通视觉误判：**881 的 s2450 写出画面未明确支持的狗；9841 的 s2349 将一女两男写成两女一男；7971 的 s2709 断言人物脸旁有手机，而所见手势不足以支持该物体。单帧隔离无法自动解决这些问题。

以上为助手审阅和具体案例判断，独立人工审阅仍未进行；不据七个已知错误帧推算整体正确率，也不宣称统计显著改善。

## 5. 推理后发现并修复的空描述问题

672 份原响应中有 **54 份 `visible` 只有逗号**。原冻结脚本将其作为带来源的事实，这是一个入库缺陷。已补充过滤回归测试，并在 `review/guarded_facts.json` 保存确定性重处理结果；原始输出、原冻结源码、账本与完成收据均未改写，没有重新推理。

过滤后有 618 条可见描述：208 条片内、410 条片外；另保留 657 条模型不确定项。这里的“可见描述”只表示非空文本，不等于内容已被证实。

另外，157 条可见描述、584 条不确定项达到预设字符上限，审阅中可见句子片段。这是字段长度和输出质量问题，不能与 `finish_reason=length` 的 token 截断混为一谈，也不能据结构有效认定内容完整。后续观察设计需处理这一问题。

## 6. 当前决定与下一步

**保留来源接口和空事实守卫；单帧观察器保持诊断用途，暂不晋级正式高光评分。** 理由是静态描述缺少动作过程、残余识别错误尚在、开销增加，而且来源元数据加剧旧证据被挤出。

下一步优先做 CPU 可验证的紧凑来源表示与记忆保留对照：保留具体时间和归属约束，避免为重复上下文淘汰关键旧证据。之后把单帧核查用于明确的身份/场景疑问；动作和结果仍需要短时连续观察。各项改动分别冻结，不同时调整比较器、观察提示和记忆排序。

后续先验证固定小规模样本，再决定是否重跑原 100 条；不降低原 +1 pp 精度门槛，不强制比较产生赢家。本轮没有新的 mAP / Hit@1。
