## 1. 目的与授权

以下数值是助手为本次明确授权任务主动采用的保守执行上限，并非用户逐项指定的数字：20 次总尝试、0 重试、0 额外故障调用、163,840 token；1 次 worker 启动、同时最多 1 卡，GPU 生命周期累计及单 worker 均不超过 900 秒。费用独立记账；旧余额不转移。

## 2. 固定输入与任务边界

沿用原固定 QV20，顺序为：9429、5172、5370、10272、8963、1058、881、8025、9196、5073、764、7795、5967、6468、1910、7050、10249、9841、7971、3202。它们来自 train 的既有开发诊断集，不能代表完整验证集表现。

每条输入保持原 query、整视频均匀 64 帧像素、真实 PTS、Qwen 视频 metadata、Qwen3-VL-8B-Instruct BF16、8192 context、2048 output cap 和确定性采样。使用已落盘帧，不重新采样、裁剪或解码。任务指令和输出 schema 改为定位，故本轮不是与旧评分实验的严格单变量因果对照。

唯一任务是找出一段最有依据的连续匹配区间。若事件多次发生，选择一个最清楚的实例，不跨无关空隙连接多次事件；不要求穷尽所有实例。没有价值分类、memory、比较器、回看、评分或音频输入。

## 3. 提示及输出契约

完整提示由 `experiments/direct_grounding/contract.py::task_text` 生成并保存于 `inputs.json`，系统与 chat wrapper 沿用原始输入。

输出仅含 `status` 和 `window`：

```json
{"status":"found","window":[32,48]}
```

`found` 要求整数秒且 `0 <= start < end <= duration`。明确认为未出现则 `{"status":"not_found","window":[]}`，证据不够则 `{"status":"uncertain","window":[]}`。不输出分数/理由，不补值、截断、修复或强迫非空。JSON grammar 限定结构和范围；解析器另检验严格正区间。整数秒是输出精度限制，64 帧间隔仍约 2 秒以上，不能声称逐帧边界精度。

## 4. 评价与反例定义

预测与 worker 退出收据冻结后才解析 GT。label 文件预先只计算 SHA256；worker 拒绝打开该标签文件。输入/提示中不注入 GT、旧分数或诊断案例。

- 主指标：R1@IoU=0.5、R1@IoU=0.7，固定全部 20 条分母。单区间取对任一 GT 区间的最大时间 IoU；并列取第一个 GT。使用本地官方 `moment_detr/standalone_eval/eval.py::compute_mr_r1` 对每条 found 输出交叉验证。
- `not_found`、`uncertain`、技术失败和未尝试在主指标中计 0；后三种与已完成的模型定位错误分开报告。绝不只报成功调用子集。
- 附加诊断：全部 20 条 best-GT IoU 的平均值，空输出/技术遗漏赋 0。这是本轮自定义 mIoU 读数，不冒充官方汇总字段。不计算排序或高光 mAP。
- 主要反例：技术调用正常，但最大 IoU < 0.5（含 abstention）；0.5≤IoU<0.7 单列严格阈值边界失败。技术错误不作为模型语义反例。
- 区间错误形态按与同一 best-IoU GT 的几何关系确定：无交集；GT覆盖≥0.8 且预测精度≤0.5 为过宽；预测精度≥0.8 且GT覆盖≤0.5 为过窄；余者部分重叠。按上述顺序判定；这不是错误原因的因果分类。

逐条保留 query、预测、全部 GT、匹配 GT、IoU、状态与错误形态。错误 GT 格式或身份不一致则停止评价，不当作模型失败。

## 5. 反例展示规则

推理完成后依据预先规则选最多 4 个展示案例：依次为无交集、过宽、过窄、部分重叠、not_found、uncertain，每类取原 QV20 顺序的首例，最多一个。所有反例仍保留在完整表格，展示选择不改变主指标或推理样本。

只用本轮输入的旧 64 帧制作带真实 PTS 的联系图。GT 可用于事后核查和标示时间，不反馈给模型。助手画面审阅是支持性诊断，不等于独立人工标注；稀疏帧无法判定时写明不确定，不把几何标签直接解释成物体/动作理解错误。若没有失败，照实报告，不增调用制造失败。
