# ReVALUE R2：候选附近配对观察执行协议

日期：2026-10-25。依据：[执行方案 v3](revalue_execution_plan_v3_2026-10-23.md) §7、§9、§10、§12。用户已要求“按原方案执行下一步”，并授权使用任意空闲 GPU。

## 阶段与问题

R1 固定 20 条已完成；决策记忆与直接比较的 VeryGood mAP / Hit@1 同为 40.10 / 55.00，未证明记忆收益。原方案未要求 R1 精度过线才能运行 R2。本次进入既有 train explore100 的 **100 条局部补看诊断**，不增加数据集或自动运行全量验证。

| 条件 | 实现与用途 |
|---|---|
| E0 | 核验复用原 P_pair |
| C_direct4 | 原候选、原帧的四态直接比较 |
| E_memory | R1 的 M_decision，作为无补看父条件 |
| E_uniform | 同一记忆和证据问题，在允许区间均匀补看 |
| E_targeted | 同一记忆和证据问题，在规划子区间定向补看 |

R1 比较、事实提取、记忆构建提示不变；观察提示沿用已通过真实 20 条验证的 v5。**R2 规划提示及其运行细节在本次实现时冻结**，不声称具体规划提示已在 R1 前完成预注册。

## 触发、采样与记忆

1. 五候选仍为 C0 原 Top-5。候选及其最多四张旧帧逐一对照父运行像素、时间戳与哈希。
2. 双向比较未决时，显式 `missing_question` 或双向判断冲突均可进入规划。冲突只提供两方向的偏好及各最多 160 字符的理由，由规划器提出≤160 字符的具体视觉查证问题；无法提出时返回无动作。“no actionable question” 不单独触发，有依据的双向平局不强制补看。规划器读取 TaskSpec、候选范围、≤1,024 token 的活动记忆及压缩后的缺口列表，不读取完整事实日志。两观察组使用同一次规划的完全相同问题。
3. 每 query 只规划一次，最多两动作。每动作指定现有缺口、相关候选、attribution/value/boundary 类型及允许区间内的起止位置；局部观察使用 Segment。允许范围为候选 2 秒格前后各扩 4 秒，并裁至源视频范围。此阶段不接纳候选外事件。
4. 每动作每组最多 24 张新增唯一源帧。逐帧验证**整个 B0** 的已见索引与 PTS，排除本组前次补看帧；两组按可用数量较小者配平，不足两张则同时取消。源帧、实际展示、重复展示、缓存与模型 padding 分开保留。
5. 观察后按同一确定性规则更新记忆：新观察事实优先，相关保留旧条目其次，其余按时间/ID 排序，完整条目裁至 1,024 token。已淘汰的原始事实不得从审计日志重新拼回。邻近上下文明确标记事件归属未确认。
6. 两组补看后各 20 次有向比较；只置换原五个分数。无可执行动作时沿用 E_memory。无语义重试；观察或规划技术失败回退有效 E_memory；其依赖失效时回退核验后的 E0，全部 100 条保留。

## 预算与并发

- 冷启动最多 92 次/query、9,200 次正式调用；R1 可复用 20×47＝940 次。复用须通过当前实际提示、schema、证据、模型及原始响应哈希核验，因此新增正式调用最多 8,260 次。
- 瞬时故障额外尝试最多 460 次，单请求最多两次；所有失败和未完成请求保留预留成本。每个方法端到端 token ≤同清单 B0 的 6 倍，计入已复用依赖；提前预留 E0 技术回退成本。
- 累计占卡时间最多 **6 GPU 小时**，包含加载、缓存复核、解码等待及失败。多卡时间相加；清理预留计入上限，排队另列。最多 8 个并发 worker、累计最多 8 次 worker 启动，900 秒无进展停止，队列最长 72 小时。
- 所有设备启动前核对空闲状态和 UUID，不终止其他任务。使用共享账本的独占锁进行原子预留，按 query 独占领取，独立 worker 状态记录；新空闲卡可在运行中加入。多卡不会重置预算或重复领取已完成样本。
- 观察组实际新增帧、问题和比较调用必须配平；故障导致未配平时如实记录并使进入确认的门槛失败。

## 验证与交付

CPU 回归覆盖无缺口 47 次、有两动作 92 次、配对取消、全 B0 帧排除、记忆无旁路、并发账本与样本锁。正式运行前对全部 100 条做源视频/父帧核验，对 940 次缓存做无模型推理的精确请求回放。

启动前的 v1 准备草稿已完成 100 条媒体核验、940 次缓存核验，未进行 GPU 推理。检查发现，仅识别显式 insufficient 问题会漏掉 R1 中 3 条 query 的 7 对双向判断冲突（另 7 对未决没有可执行问题），因此正式启动版本 v2 补齐上述冲突规划路径，并增加回归测试。旧准备目录及冻结文件保留；v2 可继承其媒体核验，重新校验视频字节，并再次回放 940 次缓存。该修正不读取标签或修改 R1 比较器，也不根据 R2 精度调提示。

推理结束并固定完整预测收据后，才加载标签计算官方 VeryGood mAP / Hit@1、Fair/Good、逐查询差值，以及 10,000 次按源视频聚类的配对 bootstrap（seed42）。

进入精度确认仍须满足：E_targeted 比四个对照中未舍入 mAP 最高者至少高 1 pp，Hit@1 相对该对照降低不超过 1 pp；技术回退不超过有效父条件且不超过 1/100；配对、完整分母及资源上限合格。最高 mAP 并列时依次选 E0、C_direct4、E_memory、E_uniform，避免事后改参考条件。

本轮完成后保存预测、原始响应、PTS/像素收据、预算、配对审计和 Markdown 报告。R3 功能检查及 R4 确认不由该队列自动启动；人工审阅仍标记未评。该协议和结果按[报告同步发布约定](report_publication_workflow.md)随下次推送发布。
