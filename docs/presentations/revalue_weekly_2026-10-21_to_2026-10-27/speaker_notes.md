# 01_本周主张

这次汇报覆盖十月二十一日至二十七日，承接上一周的实验进展。本周主要推进了 REZE 的跨数据集复现和 ReVALUE 的记忆、回看验证。先给结论：基线覆盖已经扩大，但新增记忆与定向回看还没有带来稳定的精度收益。接下来重点介绍已经完成的结果、可以确认的问题，以及下一轮应该如何用最小实验验证。

---

# 02_本周完成

本周工作分成三条线。第一条是基线覆盖：MR.HiSum 完成一千八百八十八条可用测试视频，TVSum 完成五十条视频，QFVS 完成全部一百八十个查询，SVHighlights 完成七场长视频试验。第二条是方法验证：QV 修复版 R2 的一百条全部完成，没有技术回退，但精度门槛没有通过。第三条是 TVSum 迁移和离线诊断，已经定位到任务约束误提取及记忆草稿选择损失。建议下一步先只检验错误对象约束，协议已准备，新增预算仍待授权。

---

# 03_框架边界

这里先明确方法实现到哪一步。图中是按现有代码和报告整理的主流程：REZE 通过密集初始化得到候选，随后对 Top-5 候选做任务解析、事实与决策记忆处理，再用四态比较调整排序。四种状态分别是胜、负、并列和证据不足。记忆和比较已经有局部对照，但还不能说完整自主 Agent 闭环已经验证。在 QV R2 中，实际只有七条触发配对观察，模型没有生成有效规划，动作由预设控制器规则产生。自主连续补证、事件发现、边界细化和集合选择都仍需验收。当前还依赖 REZE 初始化和旧帧，也没有证明只依赖记忆的成本优势。

# 04_数据集覆盖

这些结果需要同时看覆盖范围和任务指标。MR.HiSum 覆盖测试集的百分之九十四点四，mAP50 和 mAP15 分别是五十七和二十三点九；摘要 F1 是三十八点二七，低于常数评分经过同一个摘要选择器得到的五十六点六一。这说明局部高分排序和摘要覆盖并不是同一个问题，常数评分也不等同于随机摘要。TVSum 已完成五十条视频，主要报告固定十条验证视频的 Top-5 mAP 六十一点三二，全部五十条的五十四点八九作为补充，两种范围均高于同口径随机对照。QFVS 全查询与 SVHighlights 七场的结果也已形成，但前者没有超过均匀选片，后者属于开发试验。最后，TVHighlights 本地视频和标注仍未就绪，没有成绩，它与 TVSum 是不同数据集。各行的 mAP、Top-5 mAP 和 F1 不能直接横比。

---

# 05_QFVS结果

QFVS 上最值得注意的是，概念提示的小样本收益没有推广到全部查询。原 REZE 的 Oracle F1 是四十二点三四，单独使用概念提示为四十二点一八，反而略低。加入时间分散后达到四十四点八六，有改善，但仍低于同预算均匀选片的四十六点六二。因此不能把问题简单归结为提示不够具体，还需要分别检查语义匹配与视频覆盖。这里的全部一百八十个查询只来自四个源视频，即使排除最初四条开发查询，剩余一百七十六条也仍来自这四个视频，不能称为未见视频验证。

---

# 06_QV候选对照

QV 的候选分散实验没有达到继续采用的门槛。在固定一百条开发样本上，原 Top-5 为四十四点五八 mAP、七十八 Hit@1；分散候选为四十四点六六和七十七。mAP 精确增加零点零七九八个百分点，低于预先规定的一个百分点门槛，Hit@1 还下降了一个百分点，所以后续保留原 Top-5。页面下方单独列出上周背景：完整 val1550 的 P_pair 在十月二十日已经完成，达到四十三点七六 mAP 和七十六点八四 Hit@1，相对 B0 分别提高约零点七七和五点一六个百分点。这不是本周新实验，也不能与开发一百条直接比较均值。

---

# 07_R2结果

修复版 R2 说明工程完成与方法有效需要分开判断。一百条样本全部完成、没有技术回退，但各新增条件尚未形成稳定收益。B0 为四十四点四一 mAP、七十一 Hit@1；P_pair 保持较高的 Hit@1，达到七十八。四态直接比较和决策记忆的 mAP 只比基线略高，决策记忆的端到端 token 已接近基线的二点九倍。最关键的是，均匀观察和定向观察两组的完整预测向量都与 B0 相同，而 token 约为三倍。因此本轮不能证明新增观察有效，精度门槛没有通过。下一步需要检查补到的证据为何未改变决策，而不仅是继续增加观察次数。

---

# 08_机制诊断

本周确认了一项容量收益，但没有把它等同于精度收益。十四份固定记忆在事实和来源可还原的前提下，从一万三千八百四十 token 降到一万零三百三十九，减少百分之二十五点三，同容量补回七十五个完整旧条目。这个结果还没有证明比较器理解更好。视觉方面，三十个物体存在性问题分别使用直接核查和证据优先提示，共六十次调用，两组状态完全一样；六个参考标签为无法判断的问题，全部被给出了确定判断。另有三十七次输出探针表明，取消字符上限可以让句子更完整，但物体和人物关系误判仍存在。这些参考标签来自助手审阅，没有独立人工核验，因此只能作为定位问题的小样本证据，不能解释为总体准确率。

---

# 09_TVSum迁移

TVSum 的迁移结果进一步说明，QV 上的复评收益没有直接推广到通用高光任务。在固定十条验证视频上，候选和输入帧保持相同，B0 的 Top-5 mAP 为六十一点三二，P_pair 降至五十八点三八，下降约二点九四个百分点。四态直接比较和决策记忆都保持基线得分，两组合计四百次比较没有产生确定胜负。这一轮六百七十次调用已经完成，没有继续追加实验。接下来两页是基于既有轨迹的离线诊断，目的是区分已经查实的错误和仍待检验的原因。

---

# 10_TaskSpec错误链

第一项查实的问题发生在任务解析。TVSum 使用的是通用请求，要求找出这个视频的高光；但十条 TaskSpec 都把 Highlight of this video 误提取成了对象约束，仿佛画面里应该出现一个叫这个名字的对象。这个伪约束进入了全部四百次四态比较输入。错误及其传播已经复现，但不能因此直接断言它就是没有胜负的原因，仍需只删除该字段的单变量实验。还要特别区分，P_pair 不使用 TaskSpec，所以它的指标下降不能归因于这个错误。

---

# 11_记忆传播诊断

第二项发现是记忆证据的主要损失位置。四百四十八条事实记录中，有三百零五条在草稿选择阶段就没有被选入，进入草稿的是一百四十三条，随后只有十三条因为容量限制被移除，最终保留一百三十条。原有一百八十五条 unknown 最后只保留九条。因此，不能把证据损失主要归因于一千零二十四 token 的容量，草稿如何选择事实也需要独立检查。抽查还确认，可疑视觉描述确实进入了记忆比较，但相关比较都是并列，尚未证明导致排序下降。图中节点等宽，只表示处理阶段；CPU 契约检查也不能当作新的模型预测。

---

# 12_单变量验证

建议的下一轮非常克制：唯一改动是删除通用任务中的错误对象约束，保留原来的高光任务意图。原十条视频必须完整保留，候选、旧帧、记忆内容、比较器、排序和评价全部固定。直接比较和记忆比较各二百次，沿用旧预测作为对照，目前四百份待验证输入已经准备好，但没有新模型结果。评价时既要报告完整子集的精度，也要看错误改判、证据是否充分、合理并列和成本；不能按标注挑有利子集，也不能为了降低并列率而强迫模型分出胜负。这样才能判断错误约束是否影响了排序。

---

# 13_预算账本

执行条件需要和科学计划一起说明。QV 原诊断累计七百九十七次请求，上限一千次，消耗三十九万八千九百二十九 token，约零点五四 GPU 小时。TVSum 迁移已经用完六百七十次请求，消耗一百一十万六千九百三十二 token，约零点五八四 GPU 小时。即使 GPU 时间还有剩余，也不代表可以追加请求，QV 的余量也不能转给 TVSum。新对照建议独立设置四百次总尝试，不增加故障调用或重试，绝对上限为二百四十五万七千六百 token 和一个 GPU 小时。当前尚未授权、未启动，需要独立预算确认及新运行器审查。表中的两个账本不是全周实验总成本，本次离线诊断和汇报制作没有新增实验模型调用。

---

# 14_下一步推进

后续推进顺序是，先检验任务理解，再独立处理视觉证据和记忆保留，最后进入独立确认与长视频闭环。第一步完成 TVSum 的单变量对照。第二步检验局部细节和短时连续画面是否补足证据，以及不确定性和动作差异能否被保留下来，再评估记忆的作用。观察内容通过后，按原门槛复核 QV 一百条，然后开展独立确认和长视频 Agent 验收。我们目前还不能宣称完整记忆或回看框架带来稳定收益。此次组会希望讨论的是，是否优先给这四百次独立对照分配预算，让下一轮围绕一个可证伪的问题推进。
