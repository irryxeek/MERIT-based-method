# ReVALUE R0/R1 执行记录（2026-10-25）

## 当前状态与执行边界

依据[ReVALUE 执行方案 v3](revalue_execution_plan_v3_2026-10-23.md)，已实现独立 R0/R1 代码、完成 CPU 检查、冻结 20 条输入与源码，并启用后台队列。登记时 GPU 4/5 均有其他进程，状态为 `waiting_for_idle_gpu`，尚未开始真实模型调用，也没有新的高光指标。

后台在 GPU 4 或 5 完全空闲后启动 R0；R0 全部通过才启动 R1。每分钟检查空闲，按 UUID 核对设备，无 GPU 6 保留队列。队列 72 小时到期停止，不占用已有任务的设备。程序不自动启动 R2、R3 或全量验证；R1 结束后保留结果供诊断并继续冻结下一阶段。

代码位于零样本工作区 `experiments/revalue/`，发布副本位于 `baselines/zeroshot/experiments/revalue/`。历史 `reze_agent_v2` 和已完成预测保持原样。

| C 比较 | 五类价值；资格三态、偏好四态、双方引用；双向一致才建立胜负边 | CPU 与调用链通过，真实结果待 R0/R1 |
| B 观察基础 | Scan/Segment/Stitch 范围校验、真实源帧与 PTS；R2 配对采样排除全部 B0 已见帧 | 已核验 20 条真实 24 帧输入；模型接收容量待 R0 |

以上是基础接口及局部对照运行器的实现进度，不能将 CPU 功能测试表述为完整 Agent 的性能结果。事实与压缩文本的语义准确性仍需真实推理和人工审阅。

## 固定样本与公平对照

沿用既有 train explore100，以 SHA256(`revalue-v3:` + qid) 排序取 20 条；不因错误或分数替换样本。这些是开发样本，不是独立确认集。

固定 qid：`9429, 5172, 5370, 10272, 8963, 1058, 881, 8025, 9196, 5073, 764, 7795, 5967, 6468, 1910, 7050, 10249, 9841, 7971, 3202`。

全部使用原 C0 Top-5 候选，每个候选最多四张旧帧。已对 20 条重解码核验父 B0/P_pair 的像素、时间戳和候选收据；全部 100 条父结果也通过收据验证。模型为 Qwen3-VL-8B-Instruct，revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`，BF16、temperature 0，模型文件逐一 SHA256 核验。

| R1 条件 | 输入 | 作用 |
|---|---|---|
| E0 | 核验复用原 P_pair | 历史强基线 |
| C_direct4 | 同候选、同旧帧，无记忆 | 隔离新四态比较器及排序规则的影响 |
| M_plain | 共享事实、普通事件摘要、同旧帧 | 同容量记忆对照 |
| M_decision | 共享事实、优先保留差异/上下文/未决关系、同旧帧 | 检验保留策略 |

两种记忆构建各一次；构建输出及实际检索内容都受 1,024 tokenizer token 容量约束，完整事实日志不进入比较提示。记录实际长度、保留与淘汰 ID。比较器保留 `tie` 与 `insufficient` 的区别，不强迫未知样本产生赢家。只置换五个原分数，候选外分数保持原值。

`M_decision − M_plain` 才是本轮记忆保留策略的直接对照。`C_direct4 − E0` 包含输出协议及排序变化，不能归因于记忆。

## 工程验收和资源停止条件

22 项 CPU 行为/调用链测试通过，Ruff 检查通过；另外检查了 TaskSpec、事实、两种引用集合的记忆和比较 JSON grammar 可构建。 使用实际首条样本作 vLLM 多模态处理器 CPU 检查：两段旧帧展开为 713 个 prompt token，24 张新帧展开为 2,010 个 token，视觉网格时间维为 12（每两帧组成一个视觉单元）。这是简短工程提示的处理器检查，不是正式长提示的 token 数，也不是 GPU 生成验收。测试覆盖目的切换、事实不可变、引用归属、并列/未知、候选新增、区间扩展重选、约束不可行、预算恢复、缓存预算和完整分数导出。

R0 每条计划 1 次 TaskSpec、5 次事实、2 次记忆、3 组各 2 次方向比较、1 次真实 24 帧观察，即 15 次；20 条计划 300 次工程调用。总工程尝试上限 500，全部 20 条格式/引用/观察与三组比较均通过、预算未触发且 CPU 检查通过才放行 R1。R0 不计算高光指标，不按指标选提示。

R1 每条最多 68 次正式新调用，20 条最多 1,360 次；额外瞬时故障尝试最多 68 次。格式或语义校验失败不重生成，保留原响应并回退到核验有效的 E0，仍计入全部 20 条。正常 insufficient 单列，不能计为格式失败。修复须建立新版本，保留失败快照。

同清单 B0 输入加输出为 **581,729 token**。每个新方法端到端上限为其 6 倍，即 **3,490,374 token**；增量上限 **2,908,645 token**。共享 TaskSpec/事实按各方法独立运行的依赖计费，实际共享支出另报。下一请求发送前预留实际展开输入和最大输出；中断尝试按完整预留保守记账。

R0、R1 各最多 2 个活动 GPU 小时，含加载和失败；最多三次 worker 启动，900 秒无进度停止。终止前预留进程清理时间；排队时间不算 GPU 计算时间，也不能由重启重置资源上限。真实单卡速度尚未测得，这些上限不是完成时间承诺。
