# 全视频 2s 记忆的纯文本高光评分测试

> 发布说明（2026-10-22）：保留原报告的日期、指标和结论；调整引用链接与机器路径。历史命令和本地资料不表示本仓库附带完整运行环境，详见[报告发布约定](report_publication_workflow.md)。

## 状态与问题

已完成原 20 条训练探索样本的全视频记忆对照。300 次逻辑建库与 40 次文本评分均完成，
20 条均得到两个完整分数向量；实际请求和原始响应重放审计通过，GPU 6/7 已释放。
本轮检查取消 D0 初始化后，仅凭 2s 记忆能否产生完整高光排序，以及读取四类 cue 是否有增益。
结果未超过 D0，新增 cue 字段在本批样本上进一步降低了 mAP。

## 结果与判断

### 完整 20 条官方指标

| 条件 | VeryGood mAP | Hit@1 | 相对 D0 的 mAP 变化 | 最高分并列的查询数 |
|---|---:|---:|---:|---:|
| D0 缓存基线 | 26.07 | 30.00 | — | 19/20 |
| Memory_text：仅描述记忆 | 21.60 | 30.00 | −4.47 | 16/20 |
| Memory_cue：描述＋四类 cue | 16.53 | 20.00 | −9.54 | 17/20 |

两个新条件均为 19 ok / 1 partial，没有失败或常数回退。`partial` 对应同一条查询 qid 6150，
其两个窗口的四个 importance cue 在受限修复后仍缺参照，被程序明确标为 unknown；
描述、全部 2s 单元和最终评分均完整。D0 保留原先的 19 ok / 1 failed。

### 配对变化与基线失败影响

| 对照 | mAP 差值，百分点 | 95% 配对区间 | 胜／平／负 |
|---|---:|---|---|
| Memory_text − D0 | −4.47 | [−11.01, 2.47] | 4/3/13 |
| Memory_cue − D0 | −9.54 | [−15.05, −2.60] | 2/1/17 |
| Memory_cue − Memory_text | −5.07 | [−9.37, −1.38] | 6/5/9 |

去掉原来 D0 失败的 qid 9429 后，共同完成的 19 条上，D0 / Memory_text / Memory_cue 的
mAP 为 **26.60 / 20.24 / 14.52**，Hit@1 为 26.32 / 26.32 / 15.79。
所以下降并非由新组失败造成；恰恰是恢复了 D0 失败样本后，全 20 条的差距被部分缩小。
全 20 条仍是主结果，共同完成子集只用于解释失败策略的影响。

这组探索结果不支持当前记忆与评分方式直接替代 D0。Memory_text 相对 D0 的主区间跨零；
Memory_cue 的下降更一致，但样本仅 20 条且反复用于开发，不能据此否定一般的记忆方法。

### 离线诊断

- Memory_text / Memory_cue 分别有 6 / 5 条整段常数预测，均为模型实际输出，不是失败回退。
- 加 cue 后，1,499 个分数中有 834 个为 2.0，且所有分数落在 0–3；仅描述组有 289 个 4.0。
  分数上限不同本身不决定 mAP，值得检查的是由此伴随的并列和相对次序变化。
- novelty cue 有 1,416/1,499 条为 unknown，importance cue 有 1,421/1,499 条为 unknown。
  大量未知字段增加了文本长度，但尚不能证明未知字段就是下降原因。
- 输入 token 中位数从仅描述的 4,879.5 增至加 cue 的 18,540.5；所有请求均未超限或截断。
- qid 5516（试穿不同服装）的描述完全相同，加入 cue 后单查询 mAP 从 46.89 降至 12.27；
  qid 764（机场候机及走向飞机）从 18.00 降至 2.22。它们适合后续核查 cue 读取与排序问题。

这些现象提示应先检查记忆是否遗漏查询属性，以及评分器如何处理大量未知 cue 和长文本。
本轮没有进一步修改提示词、重跑失败例或加入工具查证；以上均为完成后独立保存的诊断。

| Memory_text 评分 | 20/20 | 98,287 | 4,765 | 0 | 117.28s |
| Memory_cue 评分 | 20/20 | 371,791 | 6,245 | 0 | 229.02s |

共 340 个逻辑请求、356 次实际请求，全部返回 `finish_reason=stop`。
16 个窗口触发一次字段修复，14 个修复后完整有效，另外两个窗口的四个 cue 降级为 unknown。
300 个窗口均可用：298 ok / 2 partial；无传输错误、截断、未知中断、窗口失败或评分失败。
基础图片展示 1,499 次，16 次修复另展示 80 次已有图片，没有回源抽取新帧。

并发工作进程耗时 **2,152.11s（约 35.9 分钟）**，不含模型启动和输入／权重核验。
建库由两组共享，计算某一种方法成本时只应加上该组评分成本，不能把两种评分都计入。
同一批样本历史 D0 为 79 个逻辑请求、80 次实际请求、325,645 输入及 26,349 输出 token；
历史请求耗时之和 1,022.10s，但服务会话和调度不同，不能据此直接报告端到端加速比。
这 20 个视频各只有一条查询，尚未测到多查询复用记忆的摊销收益；本轮全新建库开销明显。

## 固定协议

| 条件 | 评分输入 | D0 依赖 |
|---|---|---|
| D0 | 缓存的直接视觉密集评分 | 仅作为外部基线 |
| Memory_text | 原 query＋完整时间轴的 2s 描述、时间及引用 | 无 |
| Memory_cue | 同一组记忆，另提供四类 cue | 无 |

- 20 条查询对应 20 个不同视频，时间网格共 1,499 个 2s 单元。
- 与 D0 使用相同的已缓存中点 JPEG、顺序及原时间戳；先验证所有图片的像素哈希。
- 全部 300 个窗口重新建库；每次读取最多五张图片，生成五条 2s 观察，尾窗口可少于五条。
- 建库不读取 query 或 D0 分数；只提供前两个窗口位置中成功生成的描述作为上下文，不递归复制 cue。
- 记录 event/emotion/novelty/importance cue、unknown 状态及来源。novelty/importance 的已观察判断需要明确参照。
- 不生成事件图；评分时不检索候选、不输入图片、不调用工具、不回看源视频、不运行两两比较。
- 每个新条件每条查询一次完整时间轴文本评分，预计共 40 次，输出有序的 0–4 完整分数数组，允许小数。
- Memory_text 与 Memory_cue 使用完全相同的描述、节点、提示词和输出结构；仅删除或保留 `values` 字段。
- 复用 Qwen3-VL-8B-Instruct 固定权重，BF16、TP=2、temperature=0、seed=42、vLLM 0.12。
- 建库上限 8,192 输出 token；评分上限 2,048。输入在请求前核对 32,768 上下文容量，超长报错，不截断记忆。

模型仍须在建库时看图。“不用工具”指没有模型选择工具动作及回看循环；固定流程的建库与文本评分模型请求仍然存在。

## 失败与恢复

沿用结构化 JSON 输出、一次格式修复和一次传输重试。未知中断占用尝试预算，终态失败保留，不通过重复运行刷新。
无效 cue 在受限修复后可标记 unknown，并记录降级；描述等必需字段失败则标记该窗口失败，继续其余窗口。

若有窗口缺失，该查询两个新条件均不请求评分；若仅某个评分器失败，另一个条件继续执行。
新组失败使用预先规定的整条常数 2.0 向量，单独统计失败，绝不回填 D0。
常数预测在官方评估中不一定得到零指标；主结果保留 20 条完整分母，另报共同成功子集。
原来无候选的六条、D0 曾失败的一条都独立执行本轮流程。

## 指标、成本与解释范围

报告官方 VeryGood mAP、Hit@1、逐查询差值、最高分并列、记忆覆盖和失败率。
配对区间沿用 10,000 次源视频聚类 bootstrap，seed=42，所有对照均属探索。
分别记录共享建库与两个文本评分器的实际调用、重试、输入/输出 token、图片展示次数和时间。
共享并发服务的请求耗时之和不等于独立墙钟时间；缓存 D0 的原计算成本不能视为零。

Memory_text 是从同一套完整 cue 记忆中移除结构字段，描述可能已经表达 cue 语义，不能将其称作独立的“无 cue 建库”实验。
与 D0 的比较同时改变了视觉信息表达、评分提示词和批次上下文；相对旧 F2，也改变了全视频覆盖与上下文构建。
每个 2s 单元仍只有一张采样图，时间粒度不代表动作过程已经完整观察。
这 20 条已反复用于探索，不能作为独立验证结论。本轮不自动扩大样本或添加回看。
