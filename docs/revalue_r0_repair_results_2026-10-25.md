## 旧版故障与根因

v1 处理完全部 20 条 query，16 条完整通过。300 次尝试中，295 次成功、4 次输出不合法、1 次运行错误；299 个不同请求，一次 OOM 触发原预算内重试，一次失败的比较使其反向请求跳过。

| 样本 / 请求 | 实际故障 | 诊断 |
|---|---|---|
| 5172 / observation | 输出达到 512 token 后截断 | 缩进、多条重复场景描述和来源列表占用额度 |
| 8025 / observation | 输出达到 512 token 后截断 | 事实与 unknown 重复，结构冗余 |
| 7050 / observation | 首次 CUDA OOM；重试后输出截断 | 24 帧预填充余量不足；描述中又反复复述长浮点时间戳及衣着 |
| 7971 / C_direct4 / 2 / 45 | B 胜出但 A 引用为空 | 原 schema 允许空数组，后置校验才发现缺少双侧比较证据 |

OOM 日志显示 GPU 总显存约 23.52 GiB，当时仅剩约 130 MiB，申请 192 MiB 失败。vLLM 日志明确提示：手动指定的 2 GiB KV 缓存会覆盖 `gpu_memory_utilization=0.90` 的自动计算。模型加载约 16.64 GiB，24 帧视觉/预填充峰值需要额外余量。现有证据支持“容量余量不足”；不能仅凭一次日志认定内存泄漏。

## 修复过程中新发现的问题

- v2 的新增监测 RPC 被 vLLM 拒绝序列化，发生于首个生成前。v3 改用非致命外部 NVML 快照，未放宽序列化设置。
- v3 有 42 次成功比较，6 次回看却返回空事实/空未知。旧 schema 将空数组误判为成功，检查原始内容后主动停机；另 1 次已预留回看保守计费。v4 强制至少一条有来源的观察，允许明确的 `unknown`，汇总门槛再次独立拒绝空输出。

## 修复内容

- 比较与回看使用逐请求紧凑 grammar，去掉 JSON 结构缩进；TaskSpec、事实与记忆的生成设置保持原样，以便严格复用。
- 对胜负和平局在生成阶段强制双侧有效来源；`insufficient` 保留，未引用一侧必须标记 `unknown`。不把不确定强改为满足，也不补造证据。
- 回看至少包含一条观察，描述 8–96 字符，看不清时明确记为 unknown；通过来源 ID 回溯完整 PTS，避免正文重复长时间戳、衣着、环境。每条仍最多四个来源，原始 24 帧及每次输出上限保持一致。
- KV 缓存降至 1 GiB，context 为 6,144 token，prefill 批量为 1,024；启用可扩展分配段并通过进程外 NVML 保存调用前后设备显存快照；快照不等于瞬时峰值，监测异常不影响生成。发送前仍按实际多模态展开 token 检查容量。
- 加入跨版本累计账本与复用校验，保留所有旧失败。v4 复用原 160 个成功共享请求及 v3 的 42 个成功比较，新生成其余 78 次比较和全部 20 次回看；保存来源响应路径，避免跨版本 attempt 编号混淆。

## 公平性与预算

固定原 20 条、原 C0 Top-5、原旧帧和新 24 帧、相同模型 revision/BF16/temperature 0。重新解码验证像素和 PTS；输入清单与旧版逐字节保持一致。R0 不读取高光指标进行提示筛选。语义质量仍需人工审阅。

v1 为 300 次尝试、555,834 token、2,562.8754 秒、2 次 worker 启动；v2 监测失败新增 1 次预留请求、1,754 token、37.4860 秒及第 3 次启动。v3 新增 49 次尝试、109,482 token，主动停止与清理按 298.8394 秒保守计费，累计第 4 次启动。

v4 开始前合计 **350 次尝试、667,070 token、2,899.2007 秒活动 GPU 时间**。计划新增 98 次，累计 **448/500 次**，两小时活动时间上限不变。为纠正监测兼容性和空输出验收两项问题，R0 worker 启动上限分别由 3→4→5，均单独写入冻结协议和绑定文件，不能表述为原三次启动预算内完成。R1 仍最多 3 次启动；1,360 次正式请求、68 次瞬时故障追加及每方法 6 倍 B0 token 上限不变。

R0 旧失败与无信息输出没有删除或抵消费用；R1 将重新生成其正式共享依赖，不以 R0 缓存替代正式实验。

## 验证记录

v4 冻结源码的 35 项测试通过；v5 增加内容退化入口与禁止重复 R1 的两项测试，最新合计 37 项通过，Ruff 通过。回归测试覆盖：双侧引用、来源归属、ineligible 不能胜出、未知/证据不足可合法表达、实际 xgrammar 对紧凑 JSON 的接受/拒绝、观察描述长度限制、请求或响应被改动即拒绝复用、复用不重复计费、跨版本时间与 worker 次数不重置，以及监测失败不妨碍合法生成、启动例外不能用于已有模型输出，以及空观察不能通过 R0 门槛。

## v4 内容退化与隔离的 v5 修复

v4 的 20 条回看共 69 个条目全部为 `kind=unknown`，非未知事实条目为 0。相同源帧下，v1 曾输出具体可见动作；因此这里存在内容退化，不能仅凭非空与合法引用称观察器已经解决问题。新输出均值更低也伴随内容改变，不能把新旧均值差异全部归因于格式压缩。

使用实际 Qwen tokenizer 检查 grammar 后，`event`、`context`、`outcome`、`unknown` 四种测试输出均能逐 token 接受；未发现语法直接禁止非 unknown 类型。提示过度强调不确定性是待验证的解释，不能当作已证实根因。因此另建 v5 的 R0-only 诊断，固定全部 20 条帧和问题，仅恢复“先描述可见内容、再单列未知”的提示。新源码通过 37 项测试；运行在 GPU 5，保留 GPU 4 上的 v4 R1 不变，且执行器禁止重复启动 R1。完整 20 条现已完成，结果见下节。

当前 R1 诊断比较器与两种记忆保留策略，未使用这些新回看输出。其正式推理仍按原固定 20 条执行。人工语义审阅保持“未评”，R2/R3 未自动启用；完整 Agent 的有效性尚未验证。
