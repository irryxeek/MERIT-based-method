# 实验 GPU 使用约定

生效日期：2026-10-25。用户授权：**“在这个工作中，只要有空闲 gpu 都可以使用。”**

## 调度范围

本项目后续实验可使用服务器上任意空闲 GPU，不再默认限定 GPU 4/5，也不预留 GPU 6。每次启动前检查实际设备 UUID、进程、显存与利用率；其他任务正在使用的设备继续跳过。

ReVALUE 新建运行默认冻结 `gpu_candidates: "all"`，调度时扫描全部设备。只有没有计算进程、显存占用低于 512 MiB、利用率低于 5% 的卡可选；启动前再次确认，worker 校验 UUID。需要缩小范围时，在准备命令中显式传入 `--gpu-uuids UUID ...`。检查失败时不启动模型。

## 并行与现有运行

可独立拆分的后续任务优先按样本或视频分配到多张空闲卡，使用各自的结果目录与账本，汇总时核对样本覆盖及重复项。多卡实际运行时间相加计入实验 GPU 预算；扩大设备范围不自动扩大样本量或增加实验组。

当前 `revalue_r01_v4_2026-10-25` 使用冻结源码与单 worker 账本，继续在 GPU 4 运行；其原 GPU 4/5 恢复范围保留。本次不修改该运行的绑定、推理输入或预算，也不向同一账本启动并发 worker。新调度规则从下一次新建运行生效。

2026-10-25 本次资源检查中，GPU 5、7 空闲，GPU 4 执行本项目 R1，GPU 0–3、6 有其他计算进程。该记录是时间快照，启动时必须重新检查。

## 留存与发布

本约定适用于本项目后续工作，无需反复确认 GPU 编号。冻结的历史记录保留原样；新运行记录实际 GPU UUID、各 worker 成本与聚合结果。按[报告同步发布约定](report_publication_workflow.md)，下次推送同时包含本说明、调度代码及测试。
