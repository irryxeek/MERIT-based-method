# 纯记忆高光评分：结果分析与下一步优先级

> 发布说明（2026-10-22）：保留原报告的日期、指标和结论；调整引用链接与机器路径。历史命令和本地资料不表示本仓库附带完整运行环境，详见[报告发布约定](report_publication_workflow.md)。

## 结论

当前全视频 2s 记忆评分未超过 D0。更具体的发现是：**多条失败样本的查询证据已经写进记忆，
但评分器没有形成对应的排序；一次生成完整分数数组还出现了大量连续重复值。**
因此应先诊断读取与评分协议，再判断是否需要补充视觉证据或工具回看。
这轮结果不能用来否定记忆方法，也不能证明 10s 建库窗口是主要问题。

本分析只读取已经完成的固定 20 条训练探索样本，未进行新模型调用、抽帧或修改旧预测。
模型仍为 Qwen3-VL-8B-Instruct。运行协议与原始成本见[原实验报告](highlight_memory_only_2026-10-16.md)。

## 结果及可靠性边界

| 条件 | VeryGood mAP | Hit@1 | 相对 D0 的 mAP 变化 |
|---|---:|---:|---:|
| D0：直接视觉密集评分 | 26.07 | 30.00 | — |
| Memory_text：仅描述记忆 | 21.60 | 30.00 | −4.47 |
| Memory_cue：描述＋四类 cue | 16.53 | 20.00 | −9.54 |

Memory_text − D0 的配对 95% 区间为 [−11.01, 2.47]；
Memory_cue − Memory_text 为 −5.07 点，区间 [−9.37, −1.38]。
它们是反复使用的训练 20 条上的探索性统计，不是独立验证结论。

两个新条件的 40 次评分全部完成，没有评分失败、截断或常数回退。
qid 6150 的 partial 仅表示四个 importance cue 在修复后仍缺参照而被标为 unknown，
完整描述及两个评分向量均保留。去掉原 D0 失败的 qid 9429 后，19 条的 mAP 为
26.60 / 20.24 / 14.52，下降并非新组失败造成。

本次另从归档重读了全部 40 次评分的实际请求与原始响应：query、记忆顺序和描述正确传入，
两组输入只差 `values` 字段，原始分数与保存结果一致。该核查排除了这几个具体的传参与保存错误，
不意味着模型完成了可靠的逐片段理解。

## 首要问题：完整分数数组出现长段重复

这里的“末尾常数段”指从最后一个分数向前数，连续完全相同的分数数量；不代表响应被截断。

| 诊断量 | D0 | Memory_text | Memory_cue |
|---|---:|---:|---:|
| 整条视频分数相同的查询数 | 1/20 | 6/20 | 5/20 |
| 末尾至少 45 个片段分数相同 | 2/20 | 17/20 | 20/20 |
| 末尾常数段长度中位数，片段 | 3 | 64.5 | 65 |
| 最高分并列数量中位数，片段 | 13.5 | 23.5 | 53.5 |

每条视频约 75 个片段。Memory_cue 的每条输出都有最后 45–75 个片段取同一分数，
其中 65 个片段相当于 130s。D0 的唯一整段常数是其历史失败样本；新组常数均来自模型原始响应。

也不能只看 Hit@1：qid 764 的 Memory_text 前 74 项都是 0，最后一项为 0.5，
恰好命中标注而取得 Hit@1=100，但机场证据对应的多个前序片段仍是 0。
Hit@1 相同不能说明完整排序相当。

这些是优先检查长数组生成、片段定位和提示词执行的依据，尚未隔离出模型、上下文或约束解码的具体责任。
结构校验保证长度和数值范围，不保证每个分数依据了对应描述。
此外，全体片段两两比较的并列比例在 text/cue 下分别为 84.63%/80.37%，
因此不应笼统地说加 cue 后“所有并列都更多”；它增加的是本批最高分并列的严重程度，并伴随排序改变。

## 关键证据存在，仍未被利用

以下是事后挑选的解释性案例，不用于替换全 20 条分母。时间均相对于对应视频片段。

| 查询 | 保存的记忆证据 | 实际评分表现 | 可以支持的判断 |
|---|---|---|---|
| qid 688：结尾提示订阅 | 136–146s 多条描述明确包含 `SUBSCRIBE`、`COMMENT BELOW` | text 对这些片段均给 0；cue 给 2，却对开头微笑镜头给 3 | 订阅文字已经保留，优先查 query 条件下的读取与排序 |
| qid 6150：投掷橄榄球 | 106–108s 描述明确写出 `throws football toward glass box` | text 整段为 0，cue 整段为 2 | 已有动作文字未产生区分；是否真实观察到动作仍需另行视觉验证 |
| qid 764：机场候机并走向飞机 | 142–150s 包含登机牌、飞机、拖行李经过机场走廊 | cue 整段为 0；text 仅最后一段为 0.5 | 机场相关证据可读，但没有形成合理的连续片段排序 |
| qid 5516：试穿不同服装 | 前段描述分别记录多种衣服；后段还有购物、珠宝、雪地镜头 | mAP 从 text 46.89 降为 cue 12.27 | 相同描述加入 cue 后出现明显排序恶化 |

qid 5516 的标注相关区间为 0–42s：text 在该区间/其余区间的平均分为 2.67/1.94，
cue 则为 1.86/2.96，整体相对次序反转。它支持“当前 cue 读取影响了 query 排序”，
尚不能证明具体是某一类 cue 或长输入造成。

cue 相对 text 的净下降约 64.6% 来自 qid 5516、764、8083 三条；
其余 17 条平均仍下降 2.11 点。既有严重个例，也有剩余样本的总体下降。

## 记忆侧仍有哪些问题

- **有效比较证据稀少。** novelty 的 1,416/1,499 条、importance 的 1,421/1,499 条为 unknown，
  约 94.5%/94.8%。仅四条 importance 是程序强制降级，不能把大量 unknown 都归咎于校验器。
  本轮前文上下文只保留前两个窗口的描述，未生成事件图，也没有主动比较检索；
  “保存四个字段”尚不等于实现了完整的高光价值比较机制。
- **描述与 cue 尚未彻底分开。** 293/1,499 条描述包含 `level` 字样，
  如 `Status: observed. Level: 3.`。Memory_text 删除了结构化 cue，仍可能读到这些强度标记。
  因而这不是独立的无 cue 建库对照。
- **少量文本引用不一致。** 七条描述中的 `fN` 与结构化 `evidence_ids` 不同，
  例如 qid 6150 的 clip 62 引用了文字中的 f57，而结构字段为 f62。
  这是文本引用问题，不据此断言输入图片或时间戳整体错位。
- **细粒度时间不等于充分动作证据。** 每个 2s 单元仍只有一张中点图。
  qid 8083 的末段描述主要是云层、天空和黑屏，没有明确记录雷电；
  不能仅凭这些文字判断是原画面缺证据、采样错过，还是记忆遗漏。

加入 cue 后，评分输入 token 中位数由约 4,880 增至 18,541，约 3.8 倍，均未超限。
四类字段、冗余内容和输入长度一起变化，当前对照不能区分各自影响。
所有 cue 组分数都落在 0–3，但分数上限降低本身不会改变 mAP；真正需要改善的是区分与排序。

## 建议的最小后续对照

2026-10-17 已将下列建议细化为[下一轮执行方案](highlight_memory_reader_plan_2026-10-17.md)。
其中分批对照进一步保留完整输入记忆、仅缩小每次输出目标；不同时缩短输入上下文。
明确片段 ID 与引用的 R1 对照现已完成，后续阶段按预设门槛推进，见
[运行结果](highlight_memory_reader_run_2026-10-17.md)；本文仍记录原 R0/cue 的离线诊断。

**先复用现有记忆，仅诊断读取端。** 这可避免再进行 300 次视觉建库。
以下是建议，尚未执行；保持无工具、无回看和同一批开发样本。

1. 先做仅描述条件的输出协议对照：输入记忆、query、模型和评分标准不变，
   将长分数数组改为带明确 `clip_id` 与对应证据 ID 的逐片段记录。
   预先检查覆盖、顺序、query 对齐及常数尾段；一次改变输出协议，避免同时混入建库变更。
2. 如果仍未通过开发筛选，再单独测试固定短批次：每次只输出 15 个 2s 片段的评分，
   每批仍提供完整记忆、同一 query 和评分锚点。约 5 次/视频、20 条共 100 次纯文本请求；
   此对照保留全局输入，只读局部记忆的省成本方案留待后续单独评估。
3. 读取端形成合理排序后，再单独比较“只保留有证据、与 query 相关的 cue”，
   避免把 unknown 解释和通用强度大量输入。清理描述内 level 等问题应另立版本，保留旧记忆。
4. 只有证据确实缺失时再考虑回看；用预先固定的新样本检查改动是否有效，
   不能只在这 20 条或以上失败例上报告提升。

评价保留官方 mAP/Hit@1，同时报告常数输出、末尾常数段、证据引用有效性及调用成本。
不能用强制加微小差异、按标注重排或选择性重跑来消除并列。
