## 1. 当前结论

- **完整验证集基线已建立**：MERIT 在 1,550 条 validation 上为 **21.67 mAP / 31.23 Hit@1**，高于归档的四组 LongVT 完整实验。
- **VideoARM 的优势主要已在密集视觉初始化出现**：同一 419 条成功子集，初始化为 **29.01 / 44.63**，最终为 **29.45 / 45.58**。它尚未完成完整 HD 验证，不能与 1,550 条结果直接排名。
- **MERIT 后续适配尚未稳定超过简单密集评分 D0**：固定 train100 上，M0/D0/H1 为 **22.72/30.80/30.31 mAP**；局部重评分未体现附加收益。
- **固定 train20 的记忆实验尚处开发阶段**：证据图、回看、比较、2s 记忆粒度与 cue 尚未带来稳定的 mAP 改善。最新 R1 纯记忆评分为 **25.55 / 30.00**，比旧纯描述 R0 提高 **3.95 点 mAP**，但仍低于 D0 的 **26.07 / 30.00**，配对区间跨零。

上述不同样本范围分别讨论。train20 是 train100 的子集，已反复用于开发，不能将其结果直接与完整 validation 或 VideoARM 成功子集比较。

## 2. 评价口径与方法定义

### 2.1 指标与失败处理

HD 指高光检测，主指标为官方 **VeryGood mAP、Hit@1**；Fair/Good 是另外两个相关性阈值。MR 指时刻检索，使用区间 IoU 下的 mAP、R1@0.5、R1@0.7，不能与 HD mAP 混用。表中指标为百分数，差值为百分点（pp）。评估器冻结于 Moment-DETR 提交 `b7e553ac3b0c898ee6b85e03ee507c064eab89ca`。

MERIT/LongVT 主实验的失败零分**向量**仍参加官方排序评测，可能得到非零 mAP/Hit@1。后续局部记忆实验通常保留上一有效向量或 D0，并明确记录回退；VideoARM 则只对已有合法预测计算官方成功子集成绩，其“失败指标记零”另属自定义统计。`partial` 表示可选边被剔除或部分 cue 降级，不等同于整条评分失败，也不表示语义已人工核验。

区间来自各归档中按源视频聚类、10,000 次、seed=42 的配对 bootstrap，均为探索性结果；本汇总不重新挑选样本或改评分规则。小表展示四舍五入值，配对差值优先采用未舍入逐查询统计，因此与展示值直接相减可能相差 0.01 点。

### 2.2 各方法实际执行内容

| 名称 | 实际流程与边界 |
| --- | --- |
| 原 MERIT / M0 | Qwen3-VL-8B-Instruct 生成 10s 记忆，1 FPS、最长边 448；event/object/summary 三键经 Qwen3-Embedding-4B 检索，最多三轮，使用邻域证据；全视频描述与检索图像映射到 2s 高光分数。 |
| LongVT compact v1 / v2b | 冻结 `longvideotool/LongVT-RFT`；Global 使用 64 帧，Tool 另允许最多两次、每次最多 32 帧的裁剪。v2b 借鉴 GroundVTS 的分级时间片表达，没有其训练模块。 |
| VideoARM M1 | 与 MERIT 使用同一 Qwen3-VL-8B-Instruct revision。HD 先对每个 2s clip 的一张代表帧密集评分，再进入控制器选区、Scene/Clip 工具与记忆循环；图像最长边 672。 |
| D0 | 移植上述密集视觉评分接口：每个 2s clip 一张真实中点附近帧，每批最多 24 张，结合 query 直接评分 0–4。各批独立，评分前不先完整观看原视频。 |
| H1 | D0 后使用 MERIT 检索选区，局部重评分；使用相同 D0 JPEG，局部评分器没有读取记忆描述，也没有增加新帧。 |
| Memory_text / R0、Memory_cue | 为完整视频构建逐 2s 记忆，再仅凭 query 和全时间轴文字评分；分别提供描述、描述加四类 cue。没有 D0 分数输入、候选筛选或工具回看。 |
| R1 | 复用 R0 同一批描述，输出完整 `clip_id / evidence_ids / score` 记录，强化片段与分数对齐；不重新建库、不读图片。 |

MERIT 与 VideoARM 使用的 Qwen revision 为 `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`，LongVT-RFT revision 为 `16ed9314e4ea600dc4682b172a614252f2f383ad`。本项目所列实验均使用冻结权重推理，未在 QVHighlights 上训练。它们是向 QVHighlights 的任务迁移，不是复现这些论文已有的 QVHighlights 分数；模型、输入与预算差异限制了机制归因。

## 7. 调用与时间开销

### 7.1 各轮新增成本

逻辑请求指去重后的工作单元，实际尝试包含重试。图片呈现次数包含重复使用同一帧；请求秒数包含并发排队，不等于墙钟或 GPU 小时。共享 D0、记忆、D_full/R0 等历史成本不在每一行重复相加。

| 运行 | 逻辑请求 / 实际尝试 | 输入＋输出 tokens | 图片呈现 | 工作进程墙钟 |
| --- | --- | --- | --- | --- |
| train100：M0/D0/H1 共享流程 | 4,204 / 4,215 | 9,487,179 | 50,723 | 81.42 分钟 |
| train20：证据 pilot v4 | 342 / 377 | 1,379,755 | 3,759 | 15.43 分钟 |
| train20：C10/F2 修复前 | 98 / 111 | 568,200 | 755 | 12.49 分钟 |
| train20：C10/F2 修复后 | 112 / 116 | 469,420 | 860 | 7.43 分钟 |
| train20：A/B/C 输入消融 | 42 / 42 | 185,028 | 630 | 1.87 分钟 |
| train20：全片建库＋两种文字评分 | 340 / 356 | 1,611,813 | 1,579 | 35.87 分钟 |
| train20：R1 文字评分 | 20 / 20 | 142,128 | 0 | 3.00 分钟 |

这些工作进程时间均不含模型启动与权重核验；依赖缓存的实验还不含历史 D0/建库成本。pilot v1–v3 的 143 次尝试和单窗口预检 1 次另计，不能从总研究投入中删除。

全片纯记忆一轮的建库单独占 **300/316 次逻辑/实际请求、415,438 输出 tokens、7,991.98 请求秒**；R0 与 cue 评分分别为 20/20 次、117.28 与 229.02 请求秒。R1 新增 20 次、686.69 请求秒，输出 38,564 tokens，明显多于 R0 的 4,765。R1 的约 3 分钟只是复用记忆后的新增评分时间。

同 20 条历史 D0 为 79/80 次请求、351,994 总 tokens、1,022.10 请求秒；服务时段与批处理不同，不能直接算速度倍数。当前每视频只有一个 query，尚未实测多查询复用记忆后的摊销收益。

### 7.2 完整方案与历史吞吐

MERIT 完整主实验累计 VLM **57,408 次实际尝试、113.80M tokens、643,567 次图片呈现**；caption/key 占累计请求耗时约 68.1%，embedding 计算另计。原报告平均 query 17.31 秒未计完整建库和索引，不能作为端到端延迟。

| 同一批 413 条共同成功查询的历史记录 | 平均秒/查询 |
| --- | ---: |
| MERIT 记忆构建 | 36.85 |
| MERIT 查询推理 | 17.90 |
| MERIT 两阶段合计 | 54.76 |
| VideoARM active_seconds | 85.41 |

MERIT 合计不含抽帧、索引等，且对同视频多个查询重复计完整建库；VideoARM active_seconds 含查询内工作与服务等待，不能视为等条件算法速度比较。

实际记录的 MERIT 串行主运行为 **22.61 小时、68.15 成功查询/小时**；VideoARM 四路并发部分 HD 运行到暂停为 **2.75 小时、152.41 成功查询/小时**。范围、并发与计时边界不同，不构成固有 2.24 倍加速结论。

LongVT compact 的 Global/Tool 平均单样本记录为 9.09/10.98 秒，v2b 为 9.26/14.43 秒；基础模型、抽帧和服务不同，也不与上述数值直接换算算法效率。

MERIT 新适配的预热请求重放中，1/2/4 路并发的 12 请求墙钟为 70.47/50.71/43.35 秒，因此冻结四路并发。部分评分随批处理变化，该结果仅证明当时服务吞吐改善，不是完整冷启动加速。
