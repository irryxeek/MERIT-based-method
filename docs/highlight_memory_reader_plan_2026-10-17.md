## 1. 调整后的目标与方法路线

近期目标改为：**让评分器可靠地利用已有 2s 记忆，形成 query 对应的完整时间轴排序。**
保留用户提出的四类 cue、事件证据链、候选比较与按需回看的研究方向，先解决读取端问题。

| 环节 | 近期安排 | 原因 |
|---|---|---|
| 记忆构建 | 复用已完成的 1,499 条记忆，不重新建库 | 多个失败例的查询证据已经存在 |
| 基础评分 | 先用描述视图，增加明确的片段 ID 与证据引用 | 检查长数组生成和片段对应问题 |
| 批次组织 | 先全量输出；必要时仅缩小每次要评分的目标集合 | 避免同时改变输出长度与输入上下文 |
| 四类 cue | 待读取端通过开发筛选后单独测试 | 当前加 cue 使 mAP 降低 5.07 点 |
| 事件图、候选比较、源视频回看 | 延后到确有证据缺口或比较歧义时 | 当前尚不能把排序失败归因于缺少视觉信息 |
| 实验规模 | 固定原 20 条训练开发样本 | 先诊断，不扩展全量实验 |

近期流程为：

```mermaid
flowchart LR
    A[冻结的全视频 2s 记忆] --> B[仅描述视图与原 query]
    B --> C[按明确 clip_id 输出评分和引用]
    C --> D[校验覆盖并还原全长分数向量]
    D --> E[官方指标与读取行为诊断]
```

本轮评分输入不包含图片、D0 分数或标注；没有检索候选、工具动作、回看或额外 query 规划调用。
D0 仅作为外部效果参照。评分仍须区分 query 相关性与通用视觉吸引力，不能用情绪强度代替查询匹配。

## 3. 顺序对照与调用预算

| 条件 | 每次输入 | 每次输出目标 | 新增逻辑请求 | 执行条件 |
|---|---|---|---:|---|
| R0：旧数组协议 | 缓存的完整描述记忆 | 全部 74/75 个分数 | 0 | 固定基线 |
| R1：明确片段 ID 与引用 | 同一完整描述记忆 | 全部 74/75 条评分记录 | 20 | 下一轮首选 |
| R2：缩短目标输出 | 仍是同一完整描述记忆 | 连续 15 条记录，尾批保留剩余项 | 100 | R1 工程完成但未通过开发筛选时执行 |

R1 输出示意（这里只展示一条，实际要求覆盖全部目标）：

```json
{
  "clips": [
    {"clip_id": 68, "evidence_ids": ["f68"], "score": 3.0}
  ]
}
```

程序校验 `clip_id` 与目标集合完全一致、无遗漏和重复、按时间升序，以及引用来自该片段的
结构化 `evidence_ids`。低分同样需要引用所依据的观察；引用有效性不等于内容支持 query。
评分值仍由模型决定，不从 ID、cue 等级或引用数量计算。

R2 固定目标为 `[0..14]`、`[15..29]`、`[30..44]`、`[45..59]`、剩余片段。
每批都输入完整描述时间轴和同一 query，其他片段作为上下文，不读取之前批次的评分。
合并时按 ID 写回，各片段仅评分一次，不平均、不平滑、不做候选外清零。
这一步检验“缩短目标输出并明确分组”是否有帮助；尚未测试只读局部上下文的方案。

R1/R2 输出上限统一为 4,096 token，区别于 R0 的 2,048；该调整用于容纳新增字段，须写入协议和成本。
旧 R0 并未截断，不能把新组改善直接归因于提高 token 上限。
所有请求预检输入加输出上限不超过 32,768，超出时停止并记录，不截断或静默更改协议。

首轮是 **20 次纯文本请求**；若需 R2，累计为 **120 次**，新增视觉建库与读帧均为 0。
沿用一次格式修复、每个格式阶段一次传输重试：单逻辑请求最多 4 次实际尝试，
R1/R2 最坏分别为 80/400 次，重试不能视为免费。未知中断占用预算，终态失败不能刷新重跑。
实际请求、输入/输出 token、含排队请求时间和独立墙钟时间分别记录；运行时长待新输出格式实测。

## 4. 通过标准与停止规则

### 工程检查

实现后先做 CPU 检查：目标覆盖、ID 重复/错位、非法引用、数值范围、分组合并、上下文容量、
失败和恢复行为。真实推理先使用原固定顺序的前四条，只检查工程完成与资源约束；
通过后继续同一协议的其余 16 条，前四条包含在 20 条内，不另挑已知失败例当调参集。

若前四条出现终态工程失败，本轮保留为未完成协议并停止，不用不完整样本报告“全 20 条结果”。
完整运行中的单次评分终态失败，沿用整条查询常数 2.0 的失败策略并单列统计；
R2 任一批失败则该查询整体失败，保留各批原始产物，不拼接新分数与 D0 或 R0 分数。
原记忆 partial 与新的评分失败分别统计。

### 开发筛选

完整 20 条同时满足下列条件，才把该读法作为后续候选：

1. 20/20 条评分完整，合法 ID 与引用覆盖 100%，无评分失败。
2. 相对 R0 的未舍入 VeryGood mAP 提高至少 **1.00 个百分点**，Hit@1 不低于 R0 的 **30.00**。
3. “末尾至少 45 个片段同分”的查询数由 R0 的 17/20 降到 **不超过 8/20**。
   这只是重复输出的开发筛选线，不是语义质量真值；自然同分允许保留。

以上阈值是本次预先设定的资源筛选规则，不是统计显著性或研究结论。
同时报告整段常数、最高分并列、两两并列比例，以及配对 mAP/Hit@1 差值和区间。
失败样本保留在主分母；另报与 D0 共同完成的子集，避免把修复 D0 历史失败当成方法收益。

- R1 通过：结束本轮诊断，保留 R1，不自动追加 R2。
- R1 完整运行但未通过：执行 R2；对全部 20 条统一使用 R2，不按每条最优结果混合。
- R2 仍未通过：停止该轮，保留负结果，再定位提示词、模型或生成约束问题；不叠加 cue 和工具掩盖失败。
- 读取开发筛选通过，仍可能低于 D0。只有后续探索相对 D0 也有至少 1 点 mAP 增益、
  Hit@1 不下降且失败率和成本可接受，才考虑扩样检验替代价值。

人工案例检查保留订阅字幕、机场、橄榄球和试衣等例子，但只用于解释，不能代替全 20 条指标，
也不能把其标注或正确排序写入推理提示。减少重复本身不构成成功，必须同时看排序收益。

## 5. 读取端通过后，再恢复哪些研究模块

后续按顺序单独立协议，本轮预算不包含以下实验：

1. **记忆清理对照。** 固定选中的读取器，另建派生视图，去掉描述中混入的等级元数据，
   记录文本引用冲突及处理映射。保留观察事实和原始记忆，单独测量清理的效果。
   规则清理仍不能把这组记忆宣称为独立的无 cue 建库。
2. **紧凑 cue 对照。** 在同一描述视图下比较不读 cue 与读取有证据的四类 cue。
   精简 unknown 的重复解释，保留“不知道不等于没有”的语义；明确观察到的 0 与 unknown 区别处理。
   各维度不等权相加，只有与原 query 有关的内容影响评分；不新增隐藏的 query 规划模型调用。
3. **证据缺口与事件链。** 将“已有证据未被评分器利用”和“所需观察确实未记录”分开。
   前者继续检查读取；后者才测试事件前后文、源视频密集采样或比较证据。
   例如片段已有订阅文字，不应以追加视觉回看来替代读取修复。
4. **候选比较与回看。** 对多个相关候选的价值差异，再做同维度比较；若需要回看，
   保留无回看和同预算均匀回看对照。它们不纳入当前无工具轮次。
