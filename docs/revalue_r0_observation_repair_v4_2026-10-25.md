# ReVALUE R0 非空观察验收修复 v4（2026-10-25）

## 触发证据

按[监测补充 v3](revalue_r0_monitor_recovery_v3_2026-10-25.md)恢复真实生成后，42 次比较成功，6 次回看却返回 `{"facts":[],"unknown":[]}`。旧 schema 允许空列表，因而错误地将无信息响应计为成功。检查内容后主动停止运行，另有 1 个已预留的回看请求按完整预留计费。v3 保留原始标记及输出；报告明确区分“旧结构校验成功”和“有效观察”，不覆盖历史失败。

v1–v3 累计 **350 次尝试、667,070 token、2,899.2007 秒活动 GPU 时间、4 次 worker 启动**。活动时间含主动停止与保守清理记账；不是删去失败后重新计时。

## 修复内容

观察必须至少给出一条带原始帧 ID 的描述，正文 8–96 字符，最多六条。提示通常输出 1–3 条有效观察；看不清动作或结果时允许 `kind=unknown` 并明确说明缺失内容，不能为满足格式虚构事件。原 512-token 输出上限不变。

R0 汇总门槛单独检查所有 20 条是否有非空观察、是否引用实际展示的帧。空 JSON、空事实列表不能放行 R1。CPU 新增实际 grammar 拒绝空响应、接受有来源的不确定性，以及“有 24 帧输入但无有效输出仍失败”的回归检查。

其余比较提示、schema、模型、采样、输入帧、记忆和生成上限不变。保留 [v2 格式/缓存修复](revalue_r0_repair_protocol_v2_2026-10-25.md)及 v3 非致命外部显存监测。

## 复用与资源

精确核验复用原 160 个共享请求和 v3 的 42 个成功比较。每个请求都校验提示、渲染输入、证据、schema、输出上限及响应哈希；调用结果额外记录来源响应路径，防止跨运行的 attempt 编号混淆。6 个空回看均不复用。

v4 计划新生成 **78 次比较 + 20 次回看 = 98 次请求**；累计计划 **448/500 次**，额外尝试余量 52 次。活动 GPU 时间仍最多累计 **7,200 秒**，剩余约 **4,300.7993 秒**。共享事实和比较复用不重复计费，历史失败开销保留。

本次对空输出验收漏洞的修复明确增加一次工程启动机会：**R0 累计 worker 上限从 4 调至 5**；R1 仍为 3。该变更单独保存在绑定文件中，不扩大调用或活动时间上限，也不触发额外模型准确率试验。
