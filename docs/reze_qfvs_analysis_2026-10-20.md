# REZE 在 QFVS 上的四查询结果分析

> 发布说明（2026-10-22）：保留原报告的日期、指标和结论；调整引用链接与机器路径。历史命令和本地资料不表示本仓库附带完整运行环境，详见[报告发布约定](report_publication_workflow.md)。

日期：2026-10-20。分析对象为冻结的 `reze_qfvs_pilot4_v1`。**流程已正常跑通，但当前适配的摘要质量未超过简单选片对照，不宜直接扩展到 180 查询。**

本次增加的是 CPU 离线诊断，没有新增模型调用，没有修改原预测、提示、标签或摘要预算。均匀与随机对照是事后补充的诊断，不属于原先预注册的主实验。

## 1. 结果需要放在同预算对照中看

每个查询仍选取 `floor(原生片段数 × 2%)` 个 5 秒片段，使用相同 Oracle 参考摘要和语义匹配指标。均匀选片取等宽时间区间的中点；随机选片为无放回抽样，每个查询重复 1,000 次。两者均不使用查询、评分或标签来选择片段。

| 查询 | REZE F1 / % | 均匀选片 F1 / % | 随机选片平均 F1 / % | REZE − 均匀 / pp |
|---|---:|---:|---:|---:|
| P01：Desk / Face | 45.40 | 52.51 | 53.67 | −7.11 |
| P02：Building / Boat | 13.18 | 44.12 | 44.02 | −30.93 |
| P03：Book / Lady | 49.36 | 61.91 | 62.84 | −12.55 |
| P04：Garden / Hall | 46.58 | 42.07 | 41.94 | +4.51 |
| 四查询等权平均 | **38.63** | **50.15** | **50.62** | **−11.52** |

REZE 仅在 P04 上超过两种对照。P02 是最大问题，但即使不看 P02，P01 和 P03 仍低于简单选片。不能通过删除 P02 来宣称方法有效。

随机选片的四查询平均 F1，在 1,000 轮中的 2.5%–97.5% 分位为 **48.18–53.12**。这是这些固定查询上的随机选片波动范围，不是完整数据集性能的置信区间。

原报告的 Oracle Precision / Recall / F1 为 **40.81 / 37.20 / 38.63**；三位用户参考摘要的平均 F1 为 **36.26**。这两个参考集合应分别报告。

## 2. 38.63% 不是高光命中率

QFVS 根据片段的概念标签计算语义 IoU，再对机器摘要与参考摘要做最大权二分匹配。不同时间位置的片段也可能因语义相似而获得分数。因此，38.63% 不等于准确找到了 38.63% 的高光，也不能与 QVHighlights 的 mAP 直接比较。[任务与指标原文](https://arxiv.org/html/1707.04960)、[固定版本评估实现](https://github.com/showlab/UniVTG/blob/32659ac7aeba21742a63274f30eba785fc57e247/eval/qfvs.py)。

Oracle 指官方聚合的参考摘要，不是模型推理时使用标签，也不是这里的理论性能上限。

该任务的人工摘要同时保留查询相关内容与视频的重要上下文。只寻找出现查询名词的片段，并不等价于生成覆盖充分的摘要。[原论文第 4.1 节](https://arxiv.org/html/1707.04960)。

## 3. P02：优先怀疑概念歧义与动作提示不匹配

根据冻结标签：

- 全视频共有 428 个 Building 片段、2 个 Boat 片段；二者并集为 430 / 3,692。
- REZE 选中的 **73 个片段，查询概念命中为 0 / 73**。
- Oracle 摘要中，54 / 94 个片段含查询概念。
- 最高分片段的标签为 `Hands, Room, Toy`，分数约 0.726；第三高分片段为 `Hands, Toy`，约 0.677。

对最高分和第三高分片段的中点帧检查，均看到玩具组装场景。原提示仍要求模型作为 `strict video action verifier` 判断动作，而输入是 `The video shows either building or boat.`。

**工作假设：模型把名词 Building（建筑物）读成了 building（搭建动作），从而偏向组装玩具。** 标签统计、抽帧与提示共同支持优先排查这一点，但尚未做提示对照，不能声称因果已经证实。抽帧只检查了代表帧，不代表逐帧审阅全部 73 段。

## 4. P01/P03：相关性存在，摘要代表性仍不足

| 查询 | 全视频中含查询概念 | REZE 所选片段中含查询概念 | Oracle 中含查询概念 |
|---|---:|---:|---:|
| Desk / Face | 35.93% | **70.91%（39/55）** | 44.62% |
| Building / Boat | 11.65% | **0%（0/73）** | 57.45% |
| Book / Lady | 8.60% | **74.42%（32/43）** | 16.67% |
| Garden / Hall | 12.63% | **22.54%（16/71）** | 56.67% |

P01/P03 确实更倾向于选中查询概念，不能把全部结果解释为模型完全看不懂视频。但相关性提升并未转化为摘要 F1 提升。

P03 的 43 个入选片段仅形成 17 段连续区间，最长连续入选 10 个片段，即 50 秒。当前流程直接按局部分数选前 2%，没有摘要级去重或覆盖约束。**查询相关性过于集中、代表性不足是可检验的解释**；时间邻近本身不能证明语义重复，仍需要独立消融。

## 5. “几乎全是 No”不是程序全部失败

20,356 次正式评分中，20,263 次输出 No，93 次输出 Yes，No 占 **99.54%**。P01 和 P03 的所有窗口均输出 No。

但全部窗口都取得了 Yes、No 两种 token 的概率，没有 top-20 缺失回退；最终片段分数全部非零且有明显排序差异。P01 的最高片段分数约 0.310，P03 约 0.032。

这说明严格提示显著压低了肯定概率；**不能把 No 比例直接当作推理失败率，也不能仅通过提高 Yes 比例判断修复成功**。下一步应关注同预算排名与最终摘要指标。

## 6. 下一步建议：先验证适配，再扩大规模

1. **保持四查询、输入帧、窗口和 2% 预算不变，做提示对照。** 保留原 REZE 为对照，把动作核验改成视觉概念是否出现；明确 Building 指建筑物，仍采用“至少一个概念”的 OR 语义。先验证 P02 是否恢复，同时看其他查询是否下降。
2. **分别验证摘要选择。** 固定原评分，仅增加预先声明的时间邻域去重，观察是否改善覆盖；与提示改动分开，避免无法归因。不要使用真值标签做去重或选择。
3. **达到对照水平后，再用未参与这次诊断的查询检验。** 当前四查询已经用于问题定位，后续不能继续当作未见测试集。暂不直接扩大到全量 180 查询。

本轮单张 RTX 4090 的 worker 用时约 **35.05 分钟**，正式推理约 25.77 分钟、解码预处理约 8.27 分钟。每条视频只有一个查询；全部 180 查询的评分次数约为本轮 45 倍，即 **916,020 次**。简单按本轮吞吐外推约 **26 小时**，只是单卡同条件估计，未考虑调度变化。

QFVS 可以检验长视频中的语义覆盖、去重与跨查询记忆复用，但该结果并未直接验证情绪强度、精彩程度或高光价值比较。它宜作为补充任务，不替代 QVHighlights 上的 HD 主指标。
