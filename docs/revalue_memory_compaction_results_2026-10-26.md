## 2. GPU 探针：只移除两个字符上限

父 672 次单帧观察存在字段达到字符上限、句子片段和标点占位问题。本轮从固定 28 个窗口各取位置 12，再加入历史十个回归帧，去重为 **37 次请求**；覆盖七条 query 和全部 28 个窗口。28 个系统位置与回归案例分别保留选择原因，不按 GT 或本轮输出挑样。

仅删除原 JSON schema 的 `visible.maxLength=160`、`uncertainty.maxLength=80`。模型、源像素、提示、两字段、必填约束、compact EBNF、temperature 0 和 **160 个输出 token**上限不变。原条件精确复用历史响应，不重新采样；没有新增源时刻、额外重试或改写输出。

| 检查 | 原条件 | 去除字符上限 |
|---|---:|---:|
| 配对响应 | 37 | 37 |
| 结构有效 | 37 | 37 |
| token 截断 | 0 | 0 |
| 无有效 visible 内容 | 2 | 2 |
| visible 达旧 160 字符上限 | 12 | 新条件 12 条超过旧上限 |
| uncertainty 达旧 80 字符上限 | 32 | 新条件 33 条超过旧上限 |
| 助手判定的 visible 未完成片段 | 12 | 0 |

“达到上限”是机械统计；“片段/残缺表达”是助手阅读判断，二者不同。完整描述允许表达完毕的简短短语，不能只靠末尾句号判定。两条标点占位对应模糊/遮挡画面，继续作为弃答，不补造事实。25/37 条 visible 文本完全未变，另外 12 条完成原来被限制的描述。

## 3. 内容核查：文本完整不代表证据正确

助手核对全部 37 组文本和七张源像素校验通过的拼图，并对五个细节案例查看原分辨率图片。可见描述审阅记录为：**23 支持、5 矛盾、9 无法判断**；无法判断包括两个弃答。没有读取本轮 GT 或高光指标。这是含已知错误案例的开发诊断、单助手判断，**不是总体准确率，也不是独立人工验证**。

具体问题仍在：

- **7971 / s2709：**画面为脸旁抬起的空手，描述仍断言“拿着手机”。
- **881 / s2450：**水花中的细节不足以确认狗，模型仍肯定写出狗；更长的不确定项还预设了“狗的品种”。此处保留无法判断，不把模糊区域强行判成某种对象。
- **9841 / s2349 等：**右侧两人明显同处一个房间，描述仍把三人写成分别处于不同房间。
- **7971 / s216：**人物手臂/手的位置不能支持“牵手”，完整的句子仍可包含错误关系。
- 飞机画面中的“廊桥连接舱门”等细节缺乏清晰支持；单帧能描述场景，不能补证完整动作或结果。

因此保留字符限制修复作为输出接口候选，但不替换正式观察器。原 `grounded_description` 仍使用旧字段约束，新的较长文本尚未通过完整入库与容量实验；本轮没有裁剪新描述使其伪装成兼容结果。

## 5. 继续与停止决定

**P0 容量关通过，内容关未通过。** 紧凑表示尚未做模型理解等价性验证；字符上限修复只改善输出完整性。A/B/C 比较、100 条复核与全量运行均未启动，原正式 +1 pp mAP 等门槛继续有效。本轮没有新 mAP / Hit@1。

下一步先处理可核验的视觉断言：从具体证据缺口出发，区分“明确支持 / 明确矛盾 / 无法判断”，避免把模糊画面的猜测和不确定项中的预设对象变成事实。先固定一个错误类型及普通对照，例如物体是否可见，做独立小规模验证；不再直接重复 672 次广泛描述。动作、反应变化和事件结果需要短时连续输入，另立对照，不能用复制单帧代替。

自动观察器须完成固定 28 窗口和全部拟入库新事实的审查，再在统一的新事实集上冻结 A/B 各 280 次、条件通过后 C 的 280 次。不同观察事实版本不混作同因素比较；即使七条指标变化，也只算开发机制诊断。
