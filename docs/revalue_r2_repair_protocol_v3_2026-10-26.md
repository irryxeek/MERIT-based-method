# ReVALUE R2 修复与重跑协议 v3

日期：2026-10-26。用户已要求诊断、修复并重跑。依据[原执行方案 v3](revalue_execution_plan_v3_2026-10-23.md)与[R2 初版协议](revalue_r2_protocol_2026-10-25.md)；本文件明确记录新增的控制器规则与工程修复，不追溯改写旧运行。

## 保持的实验条件

仍使用原 train explore100 的全部 100 条，沿用原清单顺序、视频、C0 Top-5、候选旧帧、模型权重及官方评价器。条件为 E0、C_direct4、E_memory、E_uniform、E_targeted，附 B0 参考。事实提取、记忆压缩、比较和观察提示不变；原预测、失败响应、账本和源码快照保留。这是开发诊断，不是未见确认集或全量 val。

## 修复一：有来源的任务解析

生成前根据原 query 构造约束：object/event 的 quote 只能选原文中连续、完整词组成的片段，保留大小写、拼写、内部空格，number 必须为 null。数值约束只能选有明确数字或英文数词的输出数量、秒数或分钟数片段；count 表示请求的输出高光数，不把 “Two men” 解释为 Top-2，也不把 “winter” 解释为秒数。

同时保留生成后的严格语义校验；不对模型响应做拼写修补、引用替换或反复生成。当前数值提取器覆盖常见英文数字表达，未覆盖的复杂表达不会被猜测为预算；仍需后续请求理解评估。

全部 100 条使用同一新解析协议。所有依赖 TaskSpec 的比较重新计算；不得仅重跑失败样本然后拼成旧版结果。

## 修复二：空规划的可追溯冲突查证

先使用原规划器，一次规划、至多两动作。模型提出合法动作时直接执行；无法本地核实的 insufficient 不强制回看，有依据的双向 tie 不触发。

当双向比较出现 direction_conflict，而模型返回空动作时，新增确定性控制器：优先选冲突次数最高候选涉及的一对冲突，次数并列按候选时间/ID 排序；分别核实两端候选。问题检查原 query 中的主体/动作是否出现在目标片段，还是只出现在邻近场景，不要求模型选出赢家。定向区间为该候选 2 秒格前后各扩 1 秒，裁入原允许的 ±4 秒邻域。

这一规则是**控制器策略增补**，不能称作原模型自主规划成功。记录原模型动作、最终动作、来源、规则及缺口，评价端确定性重放。模型动作和规则动作的样本数分别报告。

两观察组共享问题、触发与调用次数；均匀组在原允许范围采样，定向组在上述子区间采样。每动作最多 24 张新增唯一源帧，排除整个 B0 及本组已见帧，按较少可行数量配平；不足两帧同时取消。记忆仍按原规则完整条目裁至 1,024 token，无原始事实旁路。

## 修复三：约束生成的引用完整性

真实回看检查发现，本地结构化输出编译器对部分平铺字符串枚举会过度接受。例如允许 `c42_f1`、`obs0_c42_f0`、`obs0_c42_f1`、`obs0_c42_f2` 时，原编译结果也接受非法的 `c42_f2`。该现象在 CPU 最小案例和实际失败请求上均可复现。

紧凑语法中的纯字符串选项改为显式前缀树，保持原允许集合，不修改事实 ID 或响应。回归同时验证拒绝拼接出来的 ID、接受全部合法 ID，并保留 unknown、insufficient、空数组和原字段关系。此修复影响约束生成的实现，旧快照保持不动。

## 验证、复用与预算

正式运行前验证旧版 7 条解析失败及最早的空冲突规划样本；该工程检查使用旧比较状态作显式夹具，真实读源帧、更新记忆并执行两组各 20 次比较，不计算精度。第一轮新增 53 次调用，解析及四次观察通过，但一次引用错误使验收失败；完整保留，第二轮修复语法后重新验证。两轮工程检查累计最多 1 GPU 小时，失败成本计入。

正式重跑只复用逐请求核验的 558 次 query-independent 事实/记忆请求和第二轮工程检查中的 8 次新协议 TaskSpec。它们必须与当前提示、schema、语法、证据、原始响应哈希完全一致。其他 TaskSpec 和全部比较重新生成。全 100 条重验源视频字节、父记录及候选证据；继承字节一致视频的全 B0 PTS 核验。

- 正式冷启动上限仍为 9,200 次；扣除 566 次精确复用，新增最多 8,634 次。额外瞬时故障尝试最多 460 次，单请求最多两次，无语义重试。
- 新一轮累计占卡最多 6 GPU 小时，多卡相加，包含加载、失败和清理；不修改上一轮 4.14 GPU 小时账本。各方法端到端 token ≤同清单 B0 的 6 倍，复用依赖计入独立成本。
- 任意空闲 GPU 均可加入，启动前检查进程、显存、利用率和 UUID；共享原子账本与 query 锁，后台 systemd 队列可断点恢复。最多 8 次 worker 启动、900 秒无进展停止、72 小时排队过期。

## 评价与停止

推理完成、预测及账本冻结后加载标签，计算官方 VeryGood mAP/Hit@1、Fair/Good、逐 query 差值及源视频聚类 bootstrap。保留全部 100 条，技术失败按原规则回退。

原精度、回退率、配平、完整分母和预算门槛保留，另要求**实际发生配对观察**；零次观察不得作为观察策略有效性的检验。报告模型动作数、控制器查证数、实际观察样本数和两组新增帧数。工程检查通过不等于精度提升。R3、R4 和全量验证均不由此队列自动启动。
